## モード判定根拠

### S/U/R スコアリング

| 軸 | スコア | 根拠 |
|---|---|---|
| **S（規模）** | **1**（小） | n=1 設計、Phase 1 で 7-8 画面、推定 ~5k 行、単一デプロイ |
| **U（不確実性）** | **2**（中） | Gemini マルチモーダル絵判定の精度 / 「悲しまない判定」の設計が新規。Sheets / Canvas は確立技術 |
| **R（リスク）** | **1**（低） | 個人利用、課金/医療/法務無し。**ただし妹さんの心理的安全性は最重要**（DONT.md A 節で防御） |
| **小計** | **4** | M1=0-3 / **M2=4+** → M2 一次判定 |

### NFR スコアリング

| カテゴリ | スコア (0-3) | コメント |
|---|---|---|
| Performance | 1 | Gemini レイテンシ吸収（待ち時間ゲーム） |
| Availability | 0 | 個人利用、ダウンタイム許容 |
| Security/Privacy | 1 | 妹さんの絵は端末ローカル中心、外部送信は判定経由のみ |
| **Accessibility** | **2** | 中学生 + 言語化苦手 + 数字苦手。UI 配慮高優先 |
| Maintainability | 1 | Sheets 連携で家族運用、非エンジニアが問題追加可 |
| **合計** | **5/15** | モード昇格オーバーライドなし |

### L2 発動閾値チェック

| 閾値 | 該当 |
|---|---|
| SPEC > 15k tok | ❌（推定 3-5k tok） |
| > 80 files / > 10k 行 | ❌ |
| domains ≥ 5 | ❌（domains=2: drawing / content） |
| 並行サブドメイン ≥ 3 | ❌ |
| 1 サイクル > 2h | ❌ |

→ **L2 不発動**

### モード判定フロー

1. L2 閾値: 全部下回る → L2 不発動 ✓
2. U=2 < 3 → 対話延長不要 ✓
3. R=1 < 2 → M2 強制ではない（ただし NFR Accessibility 2 で M2 採用）✓
4. S+U+R=4 → M2 一次判定確定 ✓

## ARC 選択根拠
