# SPEC: ケロぴの森

## WHY（目的）

中学生で「学習苦手 / 数字苦手 / 言語化苦手」だが「絵を描く / カエル / 緑」が好きな妹さんが、**学習を意識せずに学びへの理解の入口に立てる**ゲームを作る。

結果として基本教科（Phase 1: 算数〜中学数学）の理解が進む副次効果を持つ。

## WHO（対象）

n=1 設計 — 妻の妹（中学生、女子）。

特性:
- 学習に強い苦手意識。「お勉強」「学習」というワードで離脱
- 言語化が苦手 → 文字の多い UI で挫折
- 数字が苦手、特に**マイナス概念**が弱い、**文章題**が最も苦手
- 絵を描くことが好き。学校支給 iPad + スタイラスで絵や動画を見ている
- カエルが好き、緑が好き

ペルソナ拡張可能性: 同特性の他者が出てきたら拡張検討（Phase 2 以降）。

## 哲学（4 本柱・dialog-harness/philosophy.md 第 6 条「人間 ≒ Council」と整合）

| # | 柱 | 意味 |
|---|---|---|
| 1 | **絵 = 理解の証拠** | 絵が描けたら理解できている。言語化を経由せず理解度を可視化 |
| 2 | **得意から伸ばす** | 苦手の克服ではなく強みの伸長。図形 → 分数 → 量 → マイナス → 文章題の順 |
| 3 | **学習者ではなく救助者** | 妹さんは「生徒」ではなく「ケロぴの相棒」。試されるのではなく頼られる |
| 4 | **待ち時間も体験に変える** | API レイテンシは損失ではなくボーナス。ミニゲーム / 解説アニメで実質ゼロ化 |

## WHAT（機能 × 条件・Phase 1.0 MVP）

### F1. オープニング（最初の起動時のみ）

**機能**: 「世界はまだ真っ白…ケロぴを描いて、森の始まりに」のメッセージ → 妹さんがキャラを描く → 本キャラとして以降の世界に登場
**条件**:
- Phase 1.0 では仮素材（◯目玉カエル）でスキップ可能
- Phase 1.1 で本演出有効化
- 後から描き直し可能（メニュー 1 タップ）
- スキップしても進行可能（強制しない）

### F2. 森ホーム

**機能**: メインの拠点画面。ケロぴが中央、依頼の受領口・図鑑・絵巻への導線
**条件**:
- ミニマル + 差し色緑（白背景 + グレー文字 + 緑アクセント）
- 文字最小限。アイコン主体
- ケロぴが「ぴょん」とアイドル動作（200ms 以内に何か動く）

### F3. 依頼受領

**機能**: ケロぴ or 住人から自然な口調で「依頼」が届く（= 問題出題）
**条件**:
- 「問題」「テスト」「学習」というワードを使わない
- 「お困りごと」「お願い」「相談」の語彙
- 依頼者・依頼セリフ・期待する概念は **Google Sheets** から取得（F8 参照）
- 1 セッション開始時に「今日の依頼候補」を 3-5 件提示、妹さんが選ぶ
- スキップ可能（「今日はやめとく」も尊重）

### F4. 描画キャンバス

**機能**: スタイラス前提の描画 UI
**条件**:
- iPad 全画面利用、横向き優先
- 線太さ補正（指描きフォールバック対応）
- Undo / Redo / 消しゴム / 全消し / 色（最低限：緑系 3 色 + 黒 + 茶 + 青）
- 「できた！」ボタンで確定 → 判定へ
- 「描き直す」常時可能、確定後も戻れる

### F5. 判定（Gemini API）

**機能**: 描いた絵を Gemini マルチモーダルが「期待する概念」と照合
**条件**:
- 実応答時間目標: 3-10 秒（Gemini 2.x 想定）
- 体感応答時間: F6（待ち時間体験）で実質ゼロ化
- 判定は **3 段階のみ**:
  - 🌟 **大喜び**: 概念が表現されている
  - 💭 **寄り添い**: 惜しい / 違う角度。「こう考えるとどうかな？」のヒント
  - 🌱 **別角度**: もう一度描いてみる誘い（追い詰めない）
- **「不正解」「✗」「ブザー音」絶対禁止**
- 判定プロンプトは `assets/judgment-prompt.md` に切り出し（チューニング可能）
- API 失敗時はフォールバック: 「ケロぴが考え中…ちょっと待ってね」 → 既定の励ましリアクション

### F6. 待ち時間体験

**機能**: 判定中（実時間 3-10 秒）に表示する楽しみ
**条件**:
- 以下のいずれかをランダム表示:
  - **(a)** 解説の絵/図アニメ（その単元の補助イメージ。例: 分数なら蓮の葉が分割される）
  - **(b)** インスタントミニゲーム（Wii パーティ的軽さ。例: 跳ねるカエルをタップ、虫を捕まえる）
- 妹さんが「むしろこっち目当て」になっても許容する設計
- 判定結果到着時はミニゲーム途中でも「ケロぴが帰ってきた！」で自然に中断

### F7. リアクション → 図鑑 / 絵巻

**機能**: 判定結果を受け、住人が反応 → 妹さんの絵がコレクション化
**条件**:
- 大喜び → ケロぴ図鑑に住人追加 / 絵巻に妹さんの絵が追加
- 寄り添い・別角度 → 「次もよろしくね」、絵巻には保存（妹さんの全作品が残る）
- **絵巻はいつでも見返せる**（成長の可視化）

### F8. 問題プール（Google Sheets 連携）

**機能**: 問題（依頼）データをスプレッドシートで管理
**条件**:
- スキーマは `spec/domain.ts` の `Problem` 型で固定
- 列: 問題ID / 単元 / 依頼者 / 依頼セリフ / 期待する概念 / ヒント / 難易度 / 有効フラグ / Phase
- アプリは起動時 + 1 時間ごとに取得（変更があれば即反映）
- オフライン時は最終取得分でフォールバック
- Phase 1.0 MVP では 10-20 問同梱で開始

### F9. 設定 / アクセシビリティ

**機能**: 最小限の設定
**条件**:
- スタイラス / 指描き モード切替
- 効果音 ON/OFF
- フォントサイズ大/中/小
- ふりがな ON/OFF（漢字 → 中学生向けだが念のため）
- 「ケロぴを描き直す」（オープニング再演）

## Phase 別スコープ

| Phase | 単元 / 機能 |
|---|---|
| 1.0 MVP | 図形 + 分数（仮素材で全コアループ） |
| 1.1 キャラ確定 | 妹さんが描いたケロぴ取込 |
| 1.2 ビジュアル強化 | 背景・季節感・効果アニメ |
| 1.3 単元拡張 | 量 / グラフ |
| 1.4 単元拡張 | マイナス概念（数直線 / 潜水演出で視覚化） |
| 1.5 単元拡張 | 文章題（絵に翻訳して解く型） |
| **2.0** | 国 / 英 / 理 / 社 へ拡張（別 SPEC で再策定） |

## UX 制約（Must 閾値）

| 項目 | 値 | 根拠 |
|---|---|---|
| 1 問体感時間 | 1-3 分 | 飽きない |
| 1 セッション目安 | 10 分（途中離脱自由） | 「今日のぶん」感 |
| 描画 → 判定の体感待ち | ≒ 0（待ち時間ゲーム介在） | 本プロジェクト差別化 |
| 描画後アニメ反応 | 200ms 以内 | 反応性 |
| 判定 API 実時間 | ≤ 10 秒（Gemini 2.x） | 技術制約 |
| 連続失敗救済 | 2 回ハズしで別問題 or 大ヒント | 追い詰めない |
| 画面遷移 | ≤ 3 ページで主要タスク到達 | 業界標準 |

## 参考類似サービス

- **どうぶつの森** — ゆるい時間軸、住人との関係性、コレクション要素、季節感
- **Wii パーティ** — テンポ良いミニゲーム、家族で楽しめる軽さ

## データモデル進化

Phase 1 内ではスキーマ固定。Phase 2 で教科拡張時に `Problem.subject` enum を拡張する想定。
詳細は `spec/domain.ts` 参照。互換性ポリシーは additive only（既存フィールド削除禁止）。

## 非機能要件サマリ

| カテゴリ | 要求 |
|---|---|
| Performance | 待ち時間ゲーム必須、初回ロード 3 秒以内 |
| Availability | 個人利用、ダウンタイム許容 |
| Security/Privacy | 妹さんの絵は端末保存中心、外部アップロードは判定 API 経由のみ |
| **Accessibility** | **最重要**（NFR=2）。文字最小化、ふりがな、コントラスト AA |
| Maintainability | Sheets 経由で家族（非エンジニア）が問題追加可能 |
