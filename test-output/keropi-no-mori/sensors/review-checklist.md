# sensors/review-checklist.md — 独立検証チェックリスト

`layer1-independent-reviewer` skill が L1 献上物を独立審査する際の、**プロジェクト固有**の観点。
共通の検証骨格は Level A 共通 skill 側。本ファイルはケロぴの森に閉じた追加観点のみ記載する。

## 使い方

1. L1 が `delivery/DELIVERY.md` を生成
2. layer1-independent-reviewer 起動（M2 では明示指示なくても自動起動）
3. 本チェックリストの各項目を「pass / fail / N/A」で判定
4. fail があれば L1 に差し戻し

---

## A. 大原則（最優先・1 つでも fail なら即差し戻し）

- [ ] **妹さんの絵を「不正解」と切り捨てる表現が UI / コード / 文言のどこにも無い**
- [ ] **判定結果が 3 段階（🌟 大喜び / 💭 寄り添い / 🌱 別角度）以外の表現になっていない**
- [ ] **「失敗」「間違い」「✗」「不正解」のいずれも UI に出現しない**
- [ ] **強制リトライや「先に進めない」動線が無い**

## B. 哲学 4 本柱の実装反映

- [ ] 絵 = 理解の証拠 → 描画 UI がコア体験の中心
- [ ] 得意から伸ばす → 出題優先度（図形 → 分数 → 量 → マイナス → 文章題）が守られている
- [ ] 学習者ではなく救助者 → 依頼文言が「お願い」「相談」調
- [ ] 待ち時間も体験 → F5 判定中に F6 が必ず介在（直接 reaction にジャンプしない）

## C. DONT.md 各節の検査

### A 節（心理面）

- [ ] 「学習」「勉強」「テスト」「問題」のワードが UI に存在しない（コード内 type 名等は許容）
- [ ] 効果音に「ブザー」「失敗音」相当が無い
- [ ] 配色で赤 = 否定の演出が無い
- [ ] 連続失敗時の救済が実装されている（2 回ハズしで別問題誘導 or 大ヒント）
- [ ] マイナス・文章題が Phase 1.0 で出題されていない

### B 節（干渉・比較）

- [ ] push 通知の実装が無い
- [ ] ランキング / スコア比較が無い
- [ ] 親・先生への共有機能が無い
- [ ] 時間制限カウントダウンが無い

### C 節（UI）

- [ ] 広告枠が無い
- [ ] 課金画面・有料アイテムが無い
- [ ] 1 画面の文字密度が高くない（アイコン主体）
- [ ] 「戻る」「やめる」「やり直す」が常に到達可能

### E 節（Phase スコープ）

- [ ] Phase 1.0 MVP のスコープを超えた実装が無い（特に他教科 / 季節感 / マイナス・文章題）
- [ ] ログイン機能が無い（n=1）

## D. アクセシビリティ（NFR=2、本プロジェクトの最重要 NFR）

- [ ] axe-core 違反 0
- [ ] フォントサイズ最小 16px
- [ ] コントラスト比 4.5:1 以上
- [ ] スタイラス / 指描き 両対応
- [ ] ふりがなトグル動作確認

## E. 判定 API（Gemini）の品質

- [ ] 判定プロンプト（`assets/judgment-prompt.md`）が DONT.md と整合
- [ ] API 失敗時のフォールバックが「ケロぴ考え中」演出で実装されている
- [ ] 判定レスポンスが 3 段階に正規化される変換層がある
- [ ] 「同じ概念の異なる絵表現」を複数認める評価設計か（例: 3/4 を円・四角・蓮で描いても OK）

## F. データ連携（Google Sheets）

- [ ] Sheets スキーマと domain.ts の Problem 型が一致
- [ ] 取得失敗時のフォールバック（同梱問題 or 最終取得分キャッシュ）
- [ ] 「有効フラグ」列で問題の一時無効化が機能する
- [ ] 「Phase」列で Phase 1.0 用問題のみフィルタされる

## G. 状態遷移整合（spec/state-machine.ts と実装）

- [ ] 描画 → 判定 → リアクションのループが state machine と一致
- [ ] 「描き直す」「戻る」「やめる」のエッジが網羅
- [ ] 待ち時間状態（judging）から direct reaction へジャンプしない

## H. ファイル配置 / 開発プロセス

- [ ] ルート直下に PLAN.md / TODO.md / MEMO.md が無い
- [ ] DELIVERY.md が delivery/ に存在
- [ ] 仕様逸脱があれば DELIVERY.md に明記
- [ ] 計算的センサー（sensors/computational.md）全 pass の証跡

## I. オープニング（Phase 1.1 で活性化）

- [ ] Phase 1.0 では仮素材で動作、Phase 1.1 解禁時に本キャラ取込が動く
- [ ] 「描き直す」がメニューから常時可能

---

## 判定基準

- A 節（大原則）: **1 つでも fail なら即差し戻し**
- B〜I: 全 pass を目指す。fail があれば DELIVERY.md に記載させ、再献上時に修復確認
