# Decision Kit HTML v2（1 項目ずつめくる判断キット）

> v2 = 2026-10-23 kakuman-platform の認識合わせキット kit-format-1023 の回答で決めた型（upgrade-spec v6.21.0）。
> v1（全部の問いを縦に並べ、事実・図・用語を多く出す型）は使わない。問いが多くても v2 で組む。

## 起動条件

「判断キットにして」「○×で答えたい」「質問して決めたい」「認識合わせして」「選ばせて」「解説も込で選ばせて」
「モックで認識合わせ」「回答をコピーできる形で」。判断点が 2 つ以上あり推奨つきで人に返すときは明示が無くても使う。

## 最上位の規律 = 集中して理解 → 判断を素早く

1 画面に出すのは **1 項目だけ**。人は「何が困っていて（課題）、何が起きていて・どうするのか（説明）、何を決めるのか（質問）」を
読んで、**絵を見ながら**選ぶ。読む量は欄ごとの上限で絞り、細かい事実は「▸ 詳しく」に畳む（消さない）。

## 1 項目の形

| 場所 | 中身 | 上限（組み立てで超えたら知らせる） |
|---|---|---|
| 左（スマホは上） | **絵を必ず 1 枚以上**（無い項目は組み立てが止める） | — |
| 右 1 | 見出し（短い名詞） | 24 字 |
| 右 2 | **課題** = 何が困っているか | 120 字 |
| 右 3 | **説明** = いま何が起きている・どうするか（箇条） | 3 つ・各 90 字 |
| 右 4 | ▸ 詳しく（出所・細かい事実。任意） | — |
| 右 5 | **質問** = 決めること（動詞で終える 1 行） | 60 字 |
| 右 6 | **選択肢** = 2〜4 個、各 理由 1 行、AI推奨は 1 つ（灰の札） | 各 50 字・理由 60 字 |
| 右 7 | **メモ**（自由） | — |

- **複雑な項目は 2 枚に分ける**（`phases: true`）: 1 枚目 = 札「解説」（課題・説明・詳しく）、2 枚目 = 札「選ぶ」（質問・選択肢・メモ）。
  絵は両方に出す
- 選んだ案 = 紫の塗り、AI推奨 = 灰の札だけ（選んだ色と混ぜない）。選べない案は `disabled` で並べ、理由を `why` に
- キー: ← → でめくる、A〜D / 1〜4 で選ぶ。下の帯に 回答数・前へ・次へ・まとめをコピー

## 絵の決まり（原図 ＞ モック ＞ 挿絵 ＞ 表・グラフ）

| 種類 | 何か | いつ |
|---|---|---|
| **原図** `original` | 本番の図面・画面・帳票・スクショの実物（切り抜き・枠や数の描き足し可） | 問いが実物を指すとき。いちばん先 |
| **モック** `mock` | 触れる見本（`html` を埋め込む / `url` で別の Artifact を開く。`src` に代わりの画像） | 操作や流れを決めるとき |
| **挿絵** `illustration` | 実物が無いとき AI が描く見本（キャプションに「見本」「AI が描いた」） | 書き方・形の違いを見せるとき |
| **表** `table` / **グラフ** `chart` | 見比べ・数 | 上の 3 つが無いときだけ |

- 先頭の絵がいちばん大きく見える。より上の種類があるのに下の種類を先頭にすると組み立てが知らせる
- 本番の画面・図面の切り抜きは repo に入れない。spec には `{{IMG:name}}` を書き、`--images`（scratch の JSON）で公開版にだけ埋め込む

## 手順

1. **集める**: 判断点ごとに一次情報を実測（転記でなく実測、数字に出所）。起きている障害は問いにせず先に直す
2. **Council に先に回す**（技術の得失・作るか否か・時期・直し方）→ 判定を `rec` に。人に残すのは 委任の範囲 / 好み / 現場の知識
3. **項目に畳む**: 1 項目 = 1 判断。認識合わせなら 1 項目目を「この受け取り方で合っていますか」にする
4. **絵を作る**: 原図（本番を読むだけで撮る・切り抜く）→ 無ければモック（触れる見本）→ 挿絵 → 表・グラフ
5. **spec を書く**（`references/spec-schema.md`）。`summaryTitle` / `summaryFooter` は**プロンプト**として書く（下）
6. **組む**: `python scripts/build_kit2.py <spec.json> <out.html> --images <images.json> --strict`
   （絵の無い項目・上限を超えた文字・推奨の無い問いで止まる）。PC 1440 と スマホ 390 で横にはみ出さないかを
   `NODE_PATH=$(npm root -g) node scripts/check_layout.js <kit.html> <dir>` で見る（全項目とまとめを明 / 暗で撮る）
7. **渡す**: Artifact で公開して URL を渡す。spec と Markdown 正本はプロジェクトの記録の置き場へ
8. **回答が返ったら実行**: 回答まとめをプロンプトとして実行（未回答 = 推奨、メモ優先、推奨と食い違えば止めて聞く）。
   決定記録を正本に残し、出荷したら PR 番号つきの実態に直す
9. **報告**: HTML の報告書（Artifact）

## 回答まとめ = プロンプト

```
summaryTitle:
○○キット NNNN の回答です。この回答どおりに自律駆動で実行してください。処理できるものを全て完了し、最後に HTML の報告書を Artifact で出してください。

summaryFooter:
## 実行の規則
- 作業場所・1 件 = 1 PR・PR 前の検査・独立レビュー・マージ権限（「この回答が承認」）・本番は読むだけ・安全判定に止められたら止まる
- 未回答の問いは推奨の案で進める。メモがあればメモを優先し、推奨と食い違うときは止めて聞く
- 変えない決定（前の周で決まったこと）

## 回答ごとにすること
- Kn A: …。B: …（選ばれなかった案も書く）

## 作る順番
① → ② → …
```

まとめのページは 答えの表（項目・答え・メモ）+ このプロンプト + コピーのボタン。コピーできない環境では本文を選択する。

## 混同しない

- 判断を確定させるのは人。キットは「決めるための面」を作るだけ（Council / spec-architect の代わりではない）
- 障害を問いにしない。好みと権限を AI が決めない。技術の比較を人にやらせない
- 詳しい情報を消して軽くしない。**畳んで**軽くする。絵は畳まない
