# Decision Kit HTML（判断キット）

人間の一言が無いと動かない判断点を、**1 画面で ○× を付けて「回答まとめ」をコピーして返せる**形にする。
成果物は 3 つ: ① `…-DECISION-KIT-….md`（Markdown 正本）② `<date>-<topic>.json`（spec）
③ HTML 視覚版（spec から `scripts/build_kit.py` で生成。Artifact が使える環境なら公開して URL を渡す）。

> 起源: kakuman-platform-v3.0 の project skill（2026-09-02 初版 → 2026-10-10 判断キット改訂キット 1010 の回答で
> 「認知負荷を下げるのが最上位」に改訂）を DH 配布へ昇格（upgrade-spec v6.20.0）。agent 本体はプロジェクト不変で、
> プロジェクト差異は spec（JSON）と回答まとめの「実行の規則」に閉じる。

## 起動条件

「判断キットにして」「○×で答えたい」「質問して決めたい」「決めきれないので聞いて」「認識合わせして」
「HTML で展開して」「さっきの形式で」「回答をコピーできる形で」「提案を絵にして」「人間専管の整理」「起動キット」。
明示が無くても、判断点が 2 つ以上あり選択肢に推奨と却下理由を添えて人間に返す局面なら使う（Markdown だけで済ませない）。

使わない: 技術の得失の判定そのもの（→ `crosscut-council`。判定結果を本スキルの推奨にする）/ 仕様の確定・規範の新設
（→ `layer0-spec-architect`）/ 実装（→ `layer1-autonomous-dev`）/ 1 問だけで済む確認（対話で聞く）。

## 使う場面（3 用途）

| 用途 | 人にしてもらうこと | 例 |
|---|---|---|
| **不明の回答** | AI が知らない値・現場の知識を教えてもらう | 単位・原単位・業務ルール |
| **認識合わせ** | AI の受け取り方がずれていないか確かめてもらう | 「ご指示をこう受け取りました」の表 + 合っているか |
| **難問の解読** | 込み入った判断を、絵と選択肢で決めやすくして選んでもらう | 案 × 軸の得失・今 → 案の比較 |

**最上位の規律 = 答える人の認知負荷を下げる**。情報を削るのではなく、**既定で見せる物を絞り、残りは開閉で必要な人が
必要な時だけ開く**。迷ったら畳む側に倒す（ただし絵は畳まない: 文字より絵の方が情報量が多く、文字は詳細が気になった
ときに読むもの）。

| 常に見せる | 畳む（押すと開く） |
|---|---|
| 問い（動詞で終える 1 行）・回答の札・絵（原画 / 挿絵 / 図、1〜2 枚とも）・選択肢・AI推奨の 1 行 | 事実 / 決まったら（▸ 詳しく）・専門用語の説明（(i)）・答えた問い（1 行の「あなたの答え」）|

## ループの中の位置（発案 → 判断キット ⇔ Council → 実行 → 報告）

| 段 | 誰が | 出すもの |
|---|---|---|
| ① 発案 | 人 | 発話・フィードバック・前の周の残件 |
| ② 集める・分ける | AI | 一次情報の実測 + 分類（人間専管 / 1 往復 / 不可逆操作のゲート / AI 単独 / 障害） |
| ③ Council 判定 | AI（`crosscut-council`） | 技術の得失・作るか否か・時期・直し方の判定 → キットの推奨 |
| ④ 判断キット | AI | md 正本 + spec + HTML |
| ④' 応急 | AI | 起きている障害は問いにせず先に直す（キットには「問いなしで先にやること」） |
| ⑤ 回答 | 人 | ○× + メモ →「まとめをコピー」→ 貼り戻す |
| ⑥ 実行 → ⑦ 報告 | AI | 回答まとめをプロンプトとして実行し、決定記録を正本と HTML に残す |

- 人の時間を使うのは ① と ⑤ だけ。⑤ は 6〜8 問で 10 分前後が目安
- 人に出す問いは 3 種だけ = **委任の範囲 / 好み / 現場の知識**。技術の比較を人の頭の中でやらせない（Council の判定を推奨にし、人は覆すだけ）。
  逆に、好みと権限を Council に決めさせない

## なぜこの形か

- **見る物が少ないほど速く決まる**。1 問に部品が 7 種類開いていると（実測: 390px 幅で 1 問 1,429px = 画面 約 2 枚分）、
  決めるのに要らない文字まで目が拾う
- **絵で先に分かり、文字で確かめる**。事実を 5 行読むより、棒の長さ・止まる箱・●◐○ の並びを 3 秒見る方が速い
- **状態は色と形の 2 つで伝える**。選んだ案 = 紫の塗り + ✓、答えた問い = 緑の「✓ 回答済み」+ 1 行に畳む、
  まだの問い = 点線の「未回答」。AI の推奨は灰の小さな「AI推奨」札だけにし、選んだ状態と同じ色を使わない
- **AI の推奨と人間の決定を分離**する（philosophy 第 6 条 = 人間最終承認）。推奨は反証可能な事実に紐づけ、
  規律上選べない案は `disabled` にして理由を書く
- **回答は貼り戻せるテキスト**。選択は viewer のブラウザにしか残らないので「まとめをコピー」→ 対話に貼る、が唯一の返し口
- **回答まとめはプロンプト**。貼り戻される文字列だけが AI に届く。実行の規則・回答ごとの一手・順番を持たせる

## 手順

1. **集める**: 着手前に同じ件を進めている PR・ブランチが無いか見る。判断点ごとに一次情報を実測する（転記でなく実測、数字に出所）。
   起きている障害を見つけたら問いにせず先に直す（④'）
2. **分ける**: 待ちの主体で分類する。AI の準備不足で人間待ちになっている件が 0 になるまで AI 側の準備を先にやる
3. **Council に先に回す**（技術の得失・作るか否か・時期・直し方）: `crosscut-council` を起動し、判定を Q の `rec: "推奨"` にして
   invocation id を `facts` か `foot` に書く。Council と発話が一致していて確かめるだけの問いは `time: "1 分 · 確認"`
4. **問いに畳む**: 1 問 = 1 判断。選択肢は 2〜4、推奨は 1 つ（`rec: "推奨"`、次点は `"次点"`）、選べない案は
   `disabled: true` + `rec: "×理由"`。各問いに「決まったら AI が何をするか」と所要時間（1 分 · 確認 / 2 分 / 5 分 / 10 分）。
   **問いの文はシンプルに**: 1 行・動詞で終える・専門用語を避ける。避けられない用語は spec の `glossary`（用語 → 1〜2 行、
   80 字以内）に書くと、各問い・各節で最初に出た所の横に (i) が付き、押すとその場の下に開く。
   **認識合わせ**が目的なら、冒頭の節に「ご指示 → AI の受け取り方 → どの問い」の表を置き、Q1 を
   「この受け取り方で進めてよいか」（1 分 · 確認）にする
5. **spec を書く**: `references/spec-schema.md` の形で JSON。HTML を埋める欄は single quote で属性を書く。
   `summaryTitle` / `summaryFooter` は**プロンプトとして**書く（§回答まとめ）
6. **絵を入れる（既定 = 全部に絵）**: spec に宣言的な `visuals` を書くと `scripts/visuals.py` が描く（13 型、`references/visuals.md`）。
   要旨に 2〜3 枚、節ごとに 1 枚、問いごとに 1〜2 枚。
   - **原画が先**（`figures`）: 問いが図面・画面・帳票を指すなら、その部分を切り抜いて出す（1 つの点に 1 枚、押すと拡大）
   - **見え方の好みを聞く問い**: 今の画面の撮影（tag「今」）+ 案ごとの試作の撮影（tag「A」「B」…）を `figures` に並べる
     （試作は scratch の HTML を Playwright で撮る）
   - 行列 = `table` / `matrix`、今→案 = `compare` / `flow`、数 = `hbar` / `stats`
   - facts と after は「▸ 詳しく」に畳まれる。**絵と選択肢だけで決められるか**を書いた後に見直す
   - 本当に絵が要らない問いだけ `visual_skip: "理由"`。配色は `design.md` の検証済み 4 色 + 中立のみ（visuals.py が他の色を拒否する）
   - 本番の画面・図面の切り抜きは spec に `{{IMG:name}}` を置き、`scripts/inject_images.py <spec> <images.json> <out>` で
     差し替えた spec（scratch）から build する。リポジトリに入れる spec は placeholder のまま
7. **組む**: `python .claude/skills/decision-kit-html/scripts/build_kit.py <spec.json> <out.html> --strict`
   （ローカルで開くなら `--standalone`）。`--strict` は絵の無い問い・(i) の付く所に無い用語・長すぎる用語の説明を WARN にして止める。
   `--standalone` で組んだものを `NODE_PATH=$(npm root -g) node .claude/skills/decision-kit-html/scripts/check_layout.js <kit.html> <dir>`
   に通し、PC 1100px / mobile 375px（明・暗）の横はみ出しを判定、スクリーンショットで「選んだ案が塗られて ✓」「推奨の札が灰」
   「答えた問いが画面の外に出ると畳まれる」を見る（Playwright が無ければ省略し、報告に 1 行書く）。
   回答の札・畳み・▸詳しく・用語の (i)・問いの地図・下に固定の回答バー・キー操作（1〜4 / A〜D、Enter で次）はテンプレートが付ける
8. **渡す**: Artifact が使えるなら publish して URL を正本の冒頭に書く（同じファイルパスで再 publish すると URL が保たれる）。
   使えなければ HTML をファイルで渡す。正本と spec はプロジェクトの記録の置き場（`delivery/` や `docs/`）へ
9. **回答が返ったら → 実行**: 回答まとめを**プロンプトとして**実行する（未回答は推奨、メモがあればメモ優先、推奨と食い違えば止めて聞く）。
   実行の前に正本へ §決定記録（問い / 決定 / 次に AI がすること）を追記し、`scripts/add_decisions.py <spec> <decisions.json>` で
   HTML 上部に決定記録の表を足して出し直す。決定が規範改訂・skill 改訂なら、そのプロジェクトの人間承認ゲートへ
10. **報告**: 作業ごとに 直した内容 / 独立レビューの結果 / 見え方が変わる所 / 人に確かめてほしいこと。
    出荷が進んだら決定記録の「AI がすること」を PR 番号つきの実態に直す（予定のまま残さない）

## 回答まとめ = プロンプト（`summaryTitle` / `summaryFooter` の型）

```
summaryTitle:
○○キット NNNN の回答です。この回答どおりに実行してください。処理できるものを全て完了し、最後に短く報告してください。

summaryFooter:
## 実行の規則
- 作業場所（ブランチ）。着手前に同じ所を進めている PR が無いか確かめる
- 1 件 = 1 PR。PR 前に通す検査。マージ前の独立レビュー
- マージ権限（「この回答が承認」の範囲。不可逆操作は AI がマージしない）
- 本番は読むだけ / 安全判定に止められたら回避せず報告
- 未回答の問いは推奨の案で進める。メモがあればメモを優先し、推奨と食い違うときは止めて聞く
- 変えない決定（前の周で決まったこと）

## 回答ごとにすること
- Qn A: …。B: …。C: …（選ばれなかった案も書く）

## 問いなしで先にやること
- …（応急。済んでいれば PR 番号）

## 作る順番
① → ② → …（依存順）
```

- 「この回答が承認」の 1 句が、マージ権限を**キット単位**で明示する（別の周の許可を流用しない）
- 回答まとめの行の形（`Qn <short>: X（label 先頭 40 字）` / `  メモ: …` / `Qn <short>: 未回答`）は変えない

## Q カードの書き方（要点）

- **並び** = 問い（見出しに 未回答 / ✓回答済み）→ 原画・絵 → 選択肢 → AI推奨の帯 → ▸ 詳しく（事実・決まったら）→ メモ
- **問い** = 動詞で終える 1 行。用語は glossary へ
- **絵** = 問いの直下に 1〜2 枚。人間が最初に見るのはここ。推奨案は `matrix.rec` で行を灰で強調する
- **選択肢** = 10 秒で違いが分かる粒度。×案も並べる（なぜ選べないかが教育になる）。字面で伝わりにくい案は `example` か小さな `img`
- **推奨** = 灰の「AI推奨」札（紫は人が選んだ案だけ）。理由は `recWhy` に 1 文。「AI の見立てであって決定ではない」を 1 度宣言
- **事実** = 3 行前後、▸ 詳しく の中。実測値と出所（ファイル:行 / Council id）。推測は書かない
- **決まったら** = 次に AI が何をするか（作業の名前・範囲・不可逆操作の有無・所要）
- 値のヒアリングが要る問いは `extra` に空欄つきの表を入れ、構造の選択だけ ○× にする

## 混同しない

- 詳しい情報を消して軽くしない。**畳んで**軽くする（▸ 詳しく / (i) / 答えた問いの 1 行）。絵は畳まない
- 判断を確定させるのは人間。本スキルは「決めるための面」を作るだけ（spec-architect / Council の代替ではない）
- 文字だけのキットにしない。Markdown だけで済ませない（答える面は HTML、記録は Markdown）
- 障害を問いにしない。好みと権限を AI が決めない。技術の比較を人にやらせない
- 回答まとめを記録と思わない。それは次の実行のプロンプト（記録は正本の §決定記録）

## 参照

- `references/spec-schema.md` — spec JSON の全項目（`glossary`・`figures`・`table`・`{{IMG:name}}`・回答の面）
- `references/visuals.md` — 絵の型カタログ（13 型）
- `references/design.md` — 配色（検証済み）・状態色 `--ok`・選択肢 / 畳み / (i) の見た目・確認手順
- `assets/example-spec.json` — 全 13 型 + glossary の見本 spec（build して見てから型を選ぶ）
- `assets/template.html` — 生成元テンプレート（CSS + 描画 JS）
- `scripts/build_kit.py` — spec → HTML（`--strict` で絵の予算と用語を点検）/ `scripts/visuals.py` — 絵の描画
- `scripts/check_layout.js` — PC / mobile 幅のはみ出し判定 + スクリーンショット
- `scripts/inject_images.py` — `{{IMG:name}}` を data URI に差し替えた公開用 spec を作る（リポジトリの中には書かない）
- `scripts/add_decisions.py` — 回答後、spec の先頭に決定記録の節を足す（再実行で置き換え）
