# Brainstorm Orchestration — L0 ブレスト・対話支援の実行基盤（v6.11.0 F5 新設）

> L0 前ブレスト・仕様策定対話で AI が判断材料を作るときのオーケストレーション標準形。
> upgrade-spec v6.11.0 F5。**成果は常に判断材料であり判定を含まない**（I-1、escalation-matrix §3）。
> presentation 層（persona-spec.md）とは干渉しない — 本文書は logic 層の実行手段のみを定める。

## 1. 多角調査 fan-out（Workflow・既定）

ブレストの調査局面（「SNS で最新情報をキャッチアップ」「選択肢を洗い出す」等）は
決定論オーケストレーション基盤（Workflow tool）の 3 段構成を標準形とする:

```
並列リサーチ（観点別に agent() を fan-out、観点 = 情報源軸・技術軸・反面教師軸 等）
  → 構造化（schema 強制で候補を正規化: 名称 / 分類 / 適合根拠 / 出典）
  → 統合（選好軸との突合表 + 推奨案の生成。判定はしない — 選択肢と根拠の提示まで）
```

- 並列度はブレスト規模で 3〜8 目安（F7-2 の上限内）
- 反面教師（撤退談・失敗事例）の観点を必ず 1 本含める（確証バイアスの構造的抑制）
- 出典 URL を候補ごとに保持する（材料の検証可能性）
- degrade 経路（C-2）: Workflow tool 非対応環境では直列の WebSearch / WebFetch で同一 3 段を実行する

## 2. 議論型協調層の使用判断（限定 3 行）

議論型協調層（抽象契約: 独立コンテキストの複数エージェントが直接メッセージ可能・
人間割込可能・ローカル観測可能な協調層）は、以下を**すべて**満たす場面に限定する:

1. 多役割の**対立的検討そのものが成果物**である（調査・整形なら §1 の fan-out で足りる）
2. 人間が対話に割り込む価値がある（観戦しない議論は subagent fan-out と等価）
3. 並列度 ≤ 3（teammate 上限、F7-2）

実装固有情報（env・設定・既知の制約）は `../../../../templates/experimental/agent-teams.context.md`
（時限付き随時層、GA 化 or 2026-11-30 再評価）を参照。使用不能時は subagent 直列に degrade。

## 3. 成果物の置き場

- ブレスト成果は delivery/ANALYSIS-\*.md（判断材料・仕様変更なし）として記録し、L0 対話へ引き渡す
- 判断材料には「選好軸の仮説」を明示する（人間が訂正できる形にする — ブレスト成果の検証可能性）
- ブレスト内で人間が選択した事項は「ブレスト決定」として区別記録し、L0 対話で仕様化する
