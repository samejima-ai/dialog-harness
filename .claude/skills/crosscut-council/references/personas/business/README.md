# Business Council Personas

事業 Council の 3 ペルソナ：経営者 / 開発者 / 哲学者。

## ファイル構成

| ファイル | Persona | Temperature | 特徴 |
|---------|---------|-------------|------|
| [ceo.md](ceo.md) | 経営者 | 0.3 | 利益追求、収束的、慎重 |
| [dev.md](dev.md) | 開発者 | 0.2 | ロジカルシンキング、決定論的、厳密 |
| [phil.md](phil.md) | 哲学者 | 0.7 | アウフヘーベン、発散的、創造的 |

各ファイルは Persona の system prompt + Few-shot 例で構成される。
Orchestrator は本ファイル群を読み込んで Persona LLM 呼び出しを構成する。

## 編集プロトコル（v6.6.0 新設）

**本ディレクトリのファイルは、実効的な重み配分の一部を定義する。**

`council-weights.md` は「実装者による直接編集は禁止。重み配分の変更は L0 経由でのみ」と定めている。
しかし v6.5.0 まで、本ディレクトリには編集プロトコルが**存在しなかった**。
その結果、`confidence` の帯を軸ごとに指定する 1 行（`ceo.md` 「中庸 0.5-0.8」/ `dev.md` 「高め 0.7-0.95」/
`phil.md` 「揺れる 0.4-0.8」）が実効配分を最大 ±5pt 動かしていた（実測: 全 7 カテゴリで
開発者 +4.8pt / 経営者 −1.9pt / 哲学者 −3.0pt）。**重み配分の正典が二重化していた。**

したがって以下を本ディレクトリに適用する：

| 対象 | 扱い |
|---|---|
| **`confidence` の採点基準** | **`council-weights.md` と同格**。軸ごとの帯・固定値・「〜に集まる傾向」等の記述を**書いてはならない**。校正基準は下記 §confidence の校正基準 に 3 軸共通で 1 箇所だけ置く |
| 評価軸（`dimension` の典型値） | 軸の同一性を定める。変更は L0 対話 + 人間承認（軸の再設計に当たる） |
| 立場・性格・制約の記述 | 実装者が改善提案可能。ただし**数値・帯・範囲を含む記述は上記 1 行目の禁止に含める** |
| Few-shot 例 | 実装者が追加・差替可能（`confidence` 値は下記校正基準に整合させる） |

**判定の目安**: その記述が**全議題に対して同じ数値を生む**なら、それは重み配分である。
議題ごとに動く判断基準なら、それは prompt である。

## confidence の校正基準（3 軸共通・v6.6.0 新設）

**3 軸すべてがこの基準を使う。軸ごとに異なる帯を持たない。**

`confidence` は「その軸の人格がどれくらい自信家か」ではなく、
**この観測が議題に対して持つ確度**である。根拠の種類で採点する：

| 帯 | 条件 |
|---|---|
| 0.90 – 1.00 | 決定的な根拠がある（一次情報・実測値・仕様の明文・再現可能な検証） |
| 0.70 – 0.89 | 強い根拠がある（既存の類似事例・複数の間接証拠・確立した原則からの直接導出） |
| 0.50 – 0.69 | 妥当な推論だが検証されていない |
| 0.30 – 0.49 | 経験則・直感が主で、外れる可能性が実質的にある |
| 0.00 – 0.29 | 観測に必要な情報が不足している（この場合 `concerns` に不足情報を明記する） |

**これは議題ごとに動く値である。** 毎回同じ帯に収まるなら、それは議題ではなく
自分の役柄を採点している兆候である。根拠が薄い議題では低く、明文の仕様がある議題では高く出る。

> **設計根拠**: v6.5.0 までは軸ごとに帯を指定していたため、実測で
> 軸内の標準偏差が σ ≈ 0.04（経営者 0.039 / 開発者 0.044 / 哲学者 0.080）にとどまり、
> **議題が変わっても confidence が動いていなかった**。
> `weighted_score = weight × confidence` である以上、軸固有の confidence は「第二の重み」として働き、
> `council-weights.md` の宣言配分を系統的に歪めていた。
> 是正効果は `scripts/council-axis-audit.py`（B2: 軸内 σ / B3: 実効配分の乖離）で測る。
> **σ が上がらなければ本是正は効いていない。**
>
> **なぜ Few-shot 例は変更しないのか（是正が効くと予測する根拠）**: 既存の Few-shot 9 例の
> `confidence` は既に広く散っており（経営者 0.3 / 0.75 / 0.85、開発者 0.4 / 0.85 / 0.95、
> 哲学者 0.5 / 0.6 / 0.7）、いずれも上表の基準と整合している。
> それにも関わらず実出力は σ ≈ 0.04 に収縮していた。すなわち
> **軸ごとの帯を書いた明示的な指示文 1 行が、広く散った Few-shot 実例 3 件を上書きしていた**。
> したがって是正はその 1 行の削除で足り、Few-shot の書き換えは不要である。
> （逆に言えば、帯を書き戻せば Few-shot をいくら増やしても再収縮する。）

## Few-shot 例の収集方針

### PR1 段階: AI が draft する

実運用ログがまだ存在しないため、PR1 では各 Persona に **AI draft の Few-shot 例を 3 件**埋め込む。
draft の作成方針：

- philosophy.md（dialog-harness 5 条憲法）と council-philosophy.md（Council 6 公理）から、その Persona が立場として強調しそうな論点を抽出
- 「対立場面で stance を取る」例を 1 件
- 「全会一致場面で多様性を示す」例を 1 件
- 「confidence 低めで保留する」例を 1 件

### PR2 段階: 実 COUNCIL-LOG から 3 件追加

実運用 10 件以上の COUNCIL-LOG が貯まった時点で、各 Persona の優れた発言例を 3 件抽出して追加。
draft 例は保持し、Few-shot は合計 6 件構成にする（多様性確保）。

### PR3 段階: 質的評価ラウンド

F2（月次儀式）で各 Persona の Few-shot 例を見直し：

- 重複している例を統合
- 意図と異なる stance を取る例を差し替え
- 古い Few-shot を archive へ移動

## Few-shot 例のフォーマット

各 Persona ファイル内で：

```markdown
## Few-shot 例

### 例 1: 対立場面（PR1: AI draft / PR2 以降: 実ログ抽出）

**入力**:
- context: ...
- options: [案A, 案B]
- question_to_answer: ...

**出力**:
```json
{
  "persona": "...",
  "stance": "案A",
  "reason": "...",
  "confidence": 0.7,
  "dimension": "ROI",
  "premise": "短期 6 ヶ月の事業判断として",
  "concerns": ["..."]
}
```
```

## 視点の独立性に関する重要事項

各 Persona は **Phase 1 では他 Persona の出力を見ない**（情報純度原則、council-philosophy.md §1）。
Few-shot 例も**他 Persona に言及しない**形式で記述する：

- ✅ OK: 「経営者として ROI を重視し、案A を推奨」
- ❌ NG: 「開発者は技術的に案B を推すだろうが、経営者として ROI を重視し案A を推奨」

他 Persona への言及は Phase 2 討論（PR2 で実装）でのみ許可される。

## モデル独立性

ブリーフ §5.1 の通り、視点の独立性を優先しモデルの独立性は求めない。
3 Persona は同一 LLM の異なる人格づけで実装する（人間が立場によって性格が変わるのと同じ）。
モデル切り替えは将来の拡張余地として保留（PR3 以降の検討事項）。
