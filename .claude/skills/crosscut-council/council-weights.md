# Council Weights — 判定軸の優先度配分設定

この文書は Council の優先度配分（重み）を人間が編集可能な形で保持する。
Orchestrator は本文書の fenced YAML ブロックのみを機械パースする。
Markdown 本文は人間向けの文脈説明であり、機械パースしない。

## 重みとは何か（v6.5.0 で定義是正）

**重みは議決権数ではない。** 「その軸の主張を単独で通すために要する強度の閾値」である。
`weighted_score = Σ(weight × confidence)` は stance ごとの**合算**であるため、
重み 5 の単独軸は重み 3+3 の合意に敗れる（実測 11/17 で最重量軸が敗れている）。
したがって重みが表すのは「勝ちやすさ」ではなく「**その軸を取り落とした時に判定が壊れる度合い**」である。
詳細は [SKILL.md](SKILL.md) §重みの意味論。

## 編集プロトコル

- **更新タイミング**: 振り返り儀式 F1-F3（L0 対話）で人間承認を経て更新
- **更新者**: L0 が対話で抽出・提案 → 人間承認 → L0 が本ファイルを書き換える
- **実装者による直接編集は禁止**: 本ファイルの変更は重み配分の変更であり、開発者の思想・熱量を反映する判断。L0 経由でのみ更新する
- **変更履歴**: 履歴層（LC ≥ 1）では `history/CHANGELOG.md` に記録する

## 重みの計算式

```
final_weight[persona] = base_weight[persona] × ethos_multiplier
                      + situational_modifier[category][persona]
```

Orchestrator が決定論で計算する（詳細: `references/orchestrator.md`）。

## base_weights（土台重み）

**判定軸の恒常的な優先度**を表す。各 Council で合計が 10 になるように配分する。

> **v6.5.0 定義是正**: 旧記述は「開発者の思想・熱量を反映する」だった。これは
> 確定事項 F2（ペルソナは切り口の違いであり、人格・利害・物語ではない）と衝突するため、
> 「判定軸の恒常的な優先度」に是正した。重みが束縛されるのは**軸**であって、
> 軸を担う人格やその意気込みではない。

```yaml
base_weights:
  business:
    経営者: 3
    開発者: 4
    哲学者: 3
  life:
    男: 3
    父: 3
    開発者: 4  # PR3 で有効化
```

## ethos_multiplier（軸強度係数）

**そのプロジェクトにおける当該判定軸の相対的な効き幅**。デフォルトは 1.0（標準）。
プロジェクト特性に応じて L0 対話で調整する。

> **v6.5.0 定義是正**: 旧記述は「各 Persona の熱量・コミット度合い」だった。これは F2 と
> 正面衝突する（軸に人格の意気込みを持ち込む記述）。係数が調整するのは
> **軸がそのプロジェクトでどれだけ効くべきか**であり、軸を語る主体の熱意ではない。
> 名称は互換性のため `ethos_multiplier` を維持する（YAML キーの変更は既存ログとの非互換を生む）。

```yaml
ethos_multiplier:
  business:
    経営者: 1.0
    開発者: 1.0
    哲学者: 1.0
```

## situational_modifier（状況補正）

カテゴリ別の重み補正。発動元スキルが `category` として指定した値で引く。
合計は 0（ニュートラル補正）。特定カテゴリで特定軸を強化する時に正値、弱める時に負値。

デフォルト値はブリーフ §7.3 の推奨配分。

> ### ⚠ 既知の宣言違反（2026-07-26 実測で検出・**数値の是正は L0/D5 待ち**）
>
> 上記「合計は 0」の宣言に対し、以下 2 カテゴリの補正合計が **+1** になっている:
>
> | category | 経営者 | 開発者 | 哲学者 | 合計 | 実 ΣW |
> |---|---|---|---|---|---|
> | `judgment` | +1 | 0 | 0 | **+1** | 11 |
> | `conception` | 0 | −1 | +2 | **+1** | 11 |
>
> 他 5 カテゴリ（implementation / operation / maintenance / issue_triage / error_handling）は合計 0 で正常。
> **この 2 カテゴリは全発動の 74%（`history/COUNCIL-LOG.md` 54 件中 40 件）を占める**ため、
> 大半の判定が宣言と異なる ΣW=11 で走ってきた（`judgment` では経営者が、`conception` では
> 哲学者が意図より 1 だけ重い）。
>
> **本ファイル §編集プロトコル により、実装者は YAML の数値を直接編集できない**（重み配分の変更は
> 開発者の思想を反映する判断であり L0 対話 + 人間承認を要する）。したがって本注記は**欠陥の記録**であり、
> 数値の是正は L0 振り返り儀式（F1-F3）で D5 承認を経て行う。是正の選択肢は 2 つ:
>
> - (a) 合計 0 に正規化する（例 `judgment`: 経営者 +1 / 哲学者 −1、`conception`: 開発者 −1 / 経営者 −1 / 哲学者 +2）
> - (b) 「合計 0」の宣言自体を撤回し、ΣW の変動を仕様として認める（この場合 `weighted_score` の
>   閾値がカテゴリ間で非可換になる点を `consensus-protocol.md` の閾値表に明記する必要がある）
>
> **どちらを採るかで過去 40 件の再解釈可否が変わる**ため、F1 で棚卸しする。

```yaml
situational_modifier:
  implementation:   # 実装判断
    経営者: -1
    開発者: +2
    哲学者: -1
  operation:        # 運用判断
    経営者: +1
    開発者: 0
    哲学者: -1
  maintenance:      # 保守判断
    経営者: 0
    開発者: +1
    哲学者: -1
  issue_triage:     # 問題分類
    経営者: +2
    開発者: 0
    哲学者: -2
  error_handling:   # エラー対応
    経営者: -2
    開発者: +3
    哲学者: -1
  judgment:         # 判断一般
    経営者: +1
    開発者: 0
    哲学者: 0
  conception:       # 構想・新規
    経営者: 0
    開発者: -1
    哲学者: +2
```

## 計算例

`category = implementation`、business Council の場合：

```
final_weight[経営者] = 3 × 1.0 + (-1) = 2
final_weight[開発者] = 4 × 1.0 + 2   = 6
final_weight[哲学者] = 3 × 1.0 + (-1) = 2
```

（ブリーフ §7.3 の implementation 配分 `経営者 2, 開発者 6, 哲学者 2` と一致）

## 未指定カテゴリの扱い

category が上記マップに存在しない場合、Orchestrator は `judgment`（判断一般）を適用する。
COUNCIL-LOG に `category_fallback: true` を記録し、F1 で棚卸しする。

## PR1 における制限

- life Council の値は保持するが使用しない（PR3 で有効化）
- ethos_multiplier は 1.0 固定（PR3 で L0 対話連携）
- situational_modifier の動的カスタマイズは PR3 で実装
