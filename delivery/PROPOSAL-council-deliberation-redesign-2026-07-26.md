## 2. 独立観測（軸別・相互参照なし）

各軸は他軸の出力を受け取っていない。

### 2-1. 経営者軸

**Q1**
- C（投票廃止・人間直行）は献上件数を増やし、人間の処理時間が律速になる。CTL 昇格の量的条件（30→100 件）到達が遅れる。現在 56 件・`judgment_confidence` 平均 0.743（質的下限 0.7 に対し余裕が薄い）という蓄積段階では高コスト。
- B/C いずれも「統合器が 3 観測を全部読む直列フェーズ」を新設する。現行の加重和（安価な集計）に比べ 1 判定のトークンと待ち時間が確実に増える。対価が「21% で既に自由文追記として実現している統合」の形式化だけなら投資対効果は薄い。
- どの案でも `persona_summary.{stance, confidence}` の記録を続けなければ、既存 56 件は新方式と比較不能になり CTL 履歴が事実上リセットされる。**集計に使うか記録するかを分離しない変更は不可逆になる**。
- D（種別切替）は分類器という新しい維持対象を増やす。誰が規則を保守し誤分類時にどちらの経路で再実行するかが未定なら運用負荷は 2 経路分。
- A 維持で失うのは、21% の止揚案が非構造フィールドに沈むこと。検索・集計が効かず統合パターンの再利用ができない機会損失が蓄積し続ける。

**Q2**
- A は現行実装そのもので移行コストゼロ。ただし文書上で A を明示確定しなければ同じ論点が再審査され審査コストを繰り返し払う。
- B は独立観測後に相互参照ラウンドが挿入され、レイテンシが段数に比例。並列 3 呼び出しで済む速度優位を失う。

**Q3**
- 事前は全判定が毎回コストを払う。事後（残差からの逆算）は失敗時のみ。件数が多い運用では事後が有利。
- 事後検知の入力は既存 COUNCIL-LOG に既にある（止揚 21%・`human_escalated` 8・軸外 stance の退避記録）。新機構を作らず振り返り儀式 F2/F3 に載せれば維持責任者を増やさずに済む。
- 「不要」を選ぶと軸不足は `human_escalated` 増加としてのみ現れ、CTL 一致率の劣化と区別できない。**原因誤診による不要な CTL 降格**を招く。

**必須制約**
1. 軸ごとの stance と confidence を**記録**し続けること（集計に使わなくても可）。破れば既存 56 件が比較不能になり CTL 履歴が失われる。
2. 「Council 推奨 vs 実装者採用」の一致／不一致を判定できる単一の `recommended` 相当が残ること。破れば CTL の質的条件が計算不能になり委譲範囲が決まらない。
3. 撤回手順が文書化され、旧方式に戻す操作がスキーマ変更を伴わないこと。破れば撤回コストがログ再構築コストに化ける。
4. 1 判定あたりの追加段数を有限に固定すること。破れば所要時間とトークン消費に上限がなくなる。

**自己申告の非観測領域**: 判定品質そのもの／語彙が思考枠を規定しているか／3 軸が原理的に何を被覆できないか。

### 2-2. 開発者軸

**Q1**
- B/C を採ると**停止条件が消える**。現行 4 経路は全て数値比較（confidence 閾値・差 < 0.01・retry 回数）で成立しており、「統合成功」は自然文の充足判定なので閾値化できない。残るのは回数打ち切り＝水掛け論を時間で切るに等しい。
- C を採ると `auto_agree` 経路が死ぬ。CTL は判定と事後評価の一致率で育つため、**判定を出さない機構は自らを昇格させられない（自己凍結）**。
- 検算は「統合の質」には書けないが「**観測の被覆**」には書ける。各 persona の指摘が `recommended` 本文に写像されているかの被覆表は決定論で検査可能。検算対象を「正しさ」から「取りこぼしゼロ」へ置換する案なら実装できる。
- 21% が既に統合形という事実は、接頭辞一致が統合を妨げていないことを意味する。現行は「投票で骨格・自由文で統合」の二層で既に動いており、**B は新機能ではなく暗黙運用の明文化**になる。
- D は pre-check に議題分類器を増やす。誤分類は「判定不能」でなく「別の停止規則で止まる」失敗になり、ログから事後に区別できない。
- 規定外 `conflict_type` は同期スクリプトが当該フィールドを読まないため静かに通る。壊れない代わりに検知もされない。

**Q2**
- B は並列 API call を壊さず追加できるが、参照後の**再発言**を許すと 1 persona = 1 weight 不可分が崩れ、`verify_weight_calculation` の persona 一意出現検査が通らない。
- 再発言を許すなら重みは初回観測に固定し、追記は無重みの別フィールドに置く必要がある。

**Q3**
- 事後（統合残差）だけが決定論で書ける。`recommended` に写像されなかった concern 数を残差として記録すれば軸不足の兆候になる。
- 事前判定は LLM 裁量に残り、pre-check は差し戻し権を持つため誤検知が直接発動阻害になる。
- 検知のみ実装し軸追加は人間承認に閉じるのが波及最小。軸を増やすと `base_weights`・`situational_modifier` 表・`persona_summary`・council-readable「発言」節が連動する。

**必須制約**
1. 停止条件は回数または数値比較のみで表現可能であること。破れば無限 follow-up と判定未了。
2. 検算が純粋関数（入力→期待値再計算）として残ること。破れば d1m4n5 型の捏造が再発し検知不能。
3. COUNCIL-LOG は `- invocation_id:` ブロック形式を維持すること。破れば記録が CTL から静かに脱落。
4. 既存 56 件を再解釈なしで読めること。破れば CTL 履歴が断絶し信頼レベルが初期化。

**自己申告の非観測領域**: 統合解が「良い解か」の価値判定／人間側の読解負荷。

### 2-3. 哲学者軸

**Q1**
- 投票を主に残す限り、`dimension` が式に現れない現行では集計単位が「軸」ではなく「**軸の所有者**」になる。実装を変えずに A を採ると、確定事項 F1 は文言だけの宣言になる。
- B/C いずれでも `third_way_excluded` が weight 圏外という構造は残る。options 外 stance が統合入力の一級市民にならなければ、第3の道は**名前だけ保存された死蔵**になる。
- 「接頭辞一致＋自由文で他案追記」12/56 は、**投票形式が統合を密輸した痕跡**である。形式を変えなければ記録上は「案B採択」に見え続け、何を統合したかが事後に復元できない。
- 統合を主目的語に据えると、最大の失敗モードは「対立の可視化不足」から「**折衷の偽装**」へ移る。残差の出力を必須にしなければ、無理な折衷が unanimous と判別できない。
- 「投票」「熱量係数」は人間組織の物語を持ち込む。`ethos_multiplier` が「熱量・コミット度」である限り F2 と矛盾し、定義を観測の信号強度側へ移さない改称は物語を残す。

**Q2**
- 現行 A は第3条 情報純度に最も適合する。B を採るなら統合フェーズは「観測の追加」でなく「**観測の照合**」に限定されねばならない。さもなくば相互参照が同調を生み多軸性そのものを失う。
- 統合器のみが全観測を見る構造は、**統合器を最強の単一ペルソナにする非対称**を生む。統合器の出力が「どの観測をどう扱ったか」で検査可能でなければ、独立観測の価値は統合器内で消える。

**Q3**
- 事後（残差からの逆算）は献上哲学タイプ C と同型で既存の一括献上経路に載る。pre-flight は「軸設計」という L0 の仕事を Council 内部に持ち込み、非フラクタル核の境界を曖昧にする。
- 「不要」を採ると、3 軸で覆えない議題は unanimous として通過する。**全会一致を質と読む第2条の系が、被覆不足の隠蔽装置へ反転する**。

**必須制約**
1. 本審査の出力を Council 機構へ自動適用しないこと。破れば「自らの委譲境界を定める文書の自己改訂」に接近し、第6条の再帰遮断が実効を失う。
2. `council-philosophy.md` 第6条の「理想＝人間介入ゼロ」を根拠に `final_decision` 非 null 化へ進まないこと。破れば H カテゴリの人間専管が Council 内部文書から侵食される。
3. どの案でも「統合しきれなかった残差」の記録経路を必須にすること。破れば統合の失敗が成功と区別できず第2条の対立可視化が形骸化する。
4. 語彙を変えるなら**定義から**変えること（名前だけの改称禁止）。破れば人間組織の物語が実装意味論に残留する。

**自己申告の非観測領域**: 統合主化の実務的負荷／実測 56 件の判定精度／§10.7・§10.9 不在が参照ミスか思想欠落かの切り分け。

## 3. 死角マップ

### 3-1. 全軸一致論点（**未検証の共通前提の疑い**）

| # | 一致内容 | 一致の下にある未検証前提 |
|---|---|---|
| U1 | 「残差／軸ごとの指摘を記録せよ」（3軸すべて） | **記録すれば後で使われる**という前提。現行 `minority_opinion` は 56 件全件で記録されているが、それが実装に反映された証跡は `agreed_with_modification` 8 件しか無い。残差経路を増やしても同じ沈殿が起きる可能性を誰も観測していない |
| U2 | 「B は既存の暗黙運用（21% の止揚出力）の明文化に過ぎない」（開発者が明言、経営者・哲学者も前提化） | **その 21% が良い統合だった**という前提。品質評価は行われていない（哲学者・開発者とも自己申告で「品質は見えない」と述べた）。密輸された統合が良質だった保証はない |
| U3 | 「CTL を壊すな」（経営者=一致率／開発者=自己凍結／哲学者=間接） | **CTL は信頼に足る指標**という前提。事実 E5 の通り skill 内部ログ 20 件は今も同期対象外で、CTL は過去に「53 発動中 2 件」しか算入されない空文化を起こしている。CTL 自体の妥当性を誰も疑っていない |
| U4 | 「stance と confidence は記録し続けよ」（経営者が明示、開発者が制約化） | **confidence が意味のある数値**という前提。56 件で `tie_break_applied: true` が **0 件**＝一度も同点が起きていない。連続値として弁別的に使われている証拠が無い |

> **警戒**: U1〜U4 は合意ではなく、3軸が同じ死角を共有している可能性を示す。特に U3・U4 は
> 「統合案が満たすべき制約」として 3 軸すべてが挙げたため、**統合案の設計を最も強く拘束している前提**である。
> この前提が誤りなら統合案の骨格も誤る。

## 4. 統合案

**統合成功（1 点の残差を伴う）**。3軸 12 個の必須制約すべてを満たす単一案を構成できた。
ただし確定事項 F1 の実装反映のみ両立不能で、これは §5 残差 R1 として明示する（X4 統合失敗の隠蔽をしない）。

### 4-1. Q1 → **案 B（統合が主・投票はフォールバック）**、ただし停止条件を「統合の質」から「**被覆**」へ移す

開発者軸の「統合成功は閾値化できない」は正しい。これを回避する唯一の構成は、
**停止条件を統合の質ではなく観測の被覆率に置くこと**である（開発者軸が自ら示した抜け道:
「検算は統合の質には書けないが観測の被覆には書ける」）。

```
[Phase 1] 3 軸独立観測（現行のまま・変更なし）
   ↓
[Phase 3a] 統合試行（統合器 = 現 Judgment Agent の責務拡張、人格なし）
   ├ 各観測の concerns / premise / stance を「充足」または「残差」に**必ず一度だけ**分類する
   ├ 全指摘を満たす単一案を構成 → integrated_answer
   └ 出力に coverage_table（persona × 指摘 → covered / residual）を必須で含める
   ↓
[検算] verify_coverage（純粋関数・新規）
   ├ 全 persona の全指摘が covered ∪ residual に**過不足なく1回**現れるか（現行 verify_weight_calculation の
   │  「persona 一意出現検査」と同型の形式検査。統合の"良さ"は検査しない）
   ├ 不一致 → 1 回リトライ → 2 回目で integration_failed
   └ OK → 停止条件へ
   ↓
[停止条件]（すべて数値比較 — 開発者制約 1 を満たす）
   ├ residual_count == 0                  → 統合成立。停止
   ├ residual_count > 0 かつ全件が明示記録 → 「統合部分成立 + 残差宣言」で停止（隠蔽禁止）
   └ integration_failed（構成不能・両立不能） → [Phase 3b] フォールバックへ
   ↓
[Phase 3b] フォールバック = **現行の加重投票をそのまま実行**
   ├ compute_weight_scores / verify_weight_calculation を無改変で呼ぶ
   └ 「どの制約が両立不能だったか」を integration_failure_reason に記録
```

**追加段数は最大 1**（統合試行 1 → 失敗ならフォールバック 1）。経営者制約 4 を満たす。
**投票は廃止しない**（案 C を採らない）。理由は開発者軸の「判定を出さない機構は自らを昇格させられない（自己凍結）」。
**案 D は採らない**。理由は B4（両軸から負の観測のみ、支持観測ゼロ）。

### 4-2. Q2 → **案 A（完全独立観測）を明文で確定**。相互参照は導入しない

- 現行実装は既に A（§1-2）。**変更ゼロ**。経営者制約「移行コスト」を最小化しつつ、
  「文書上で確定しないと再審査コストを繰り返す」という同軸の指摘に応える。
- 統合器の制約を 2 点追加する（哲学者「統合器が最強の単一ペルソナになる非対称」への応答）:
  1. 統合器は**観測を生成しない**（照合と再構成のみ。4 人目の軸にならない — 現行 `judgment-agent.md` §中立性の延長）
  2. 統合器の出力は `coverage_table` で「どの観測をどう扱ったか」が**外部から検査可能**であること
- Phase 2（相互参照）の PR2 予告は**取り下げ候補**として D5 に上申する（B2: 再発言は weight 不可分を壊し、
  照合を超える相互参照は同調を生む。両軸が無条件採用を否定した）。

### 4-3. Q3 → **事後（統合残差からの逆算）に一元化**。事前は置かない

- 判定原理は HANDOFF 記載どおり「統合結果に説明不能な残差があるなら軸不足のシグナル」。
  これを `residual_count` として**既に決定論で得られる値**にする（4-1 の副産物であり新機構ではない）。

- **軸の追加は人間承認に閉じる**（開発者「検知のみ実装し軸追加は人間承認」＋哲学者「軸設計は L0 の仕事で、
  pre-flight は非フラクタル核の境界を曖昧にする」）。したがって `§10.9 相当の「一発使い捨て派生／
  反対意見専門派生」の運用手順`は **Council 内部ではなく L0 側の手順として起草する**（本審査の射程外）。

### 4-4. 付帯論点（語彙）→ **本審査では改称しない**

  名称だけが先に動いて物語が残る = 哲学者制約 4 違反になる）。

## 6. D5 への献上文

判断を要する点のみ。3 項目。

### 献上 1: Q1 の採否 — 案 B（被覆検査つき統合を主・投票をフォールバックへ降格）

3 軸の 12 制約すべてを満たす構成を §4 に示した。核心は**停止条件を「統合の質」から「観測の被覆」へ移すこと**で、
これにより「統合は機械判定できない」という開発者軸の反論を、投票を廃止せずに解消できる。
投票は廃止しない（廃止すると機構が自らを昇格させられない）。案 D は支持観測ゼロで却下。

**ただし採否の前に R4 を認識されたい**: 現行 56 件で加重投票が判定を分岐させた事例は実質ゼロ
（`judgment_failed` 0／`tie_break` 0）。**「投票は情報を捨てる」という仮説は正しいが、
そもそも投票がほとんど何も決めていなかった可能性がある**。この場合、案 B の効果は
「情報の回復」ではなく「既に自由文で行われていた統合（21%）の構造化」に留まる。
効果の見積りをどちらで置くかは D5 の判断を要する。

### 献上 2: F1 の実装反映方法（R1）

重みキーを persona から判定軸へ移す作業は、既存 56 件のログ資産との互換性を必ず破る。3 択：

| 案 | 内容 | 代価 |
|---|---|---|
| ① | `base_weights` を dimension キーへ移行、旧エントリは旧版として版分岐 | CTL 履歴の連続性に断層 |
| ② | フォールバック投票時のみ軸キーを使う（統合主経路では重みを使わない） | 二重スキーマの維持負荷 |
| ③ | F1 は宣言として保持し実装は persona キー維持 | 哲学者軸「F1 が文言だけの宣言になる」を受け入れる |

**②が §4 の統合案と最も整合する**（統合主化により投票の発火頻度が下がるため、
二重スキーマの露出面が小さい）。ただし決定は D5。

### 献上 3: `ethos_multiplier` の定義が F2 と衝突している（次元判定を要する）

`council-weights.md:41` は `ethos_multiplier` を「各 Persona の**熱量・コミット度合い**」と定義している。
これは F2（ペルソナは切り口の違いであり、人格・利害・物語ではない）と正面衝突する。
D4 文書内の定義矛盾であり、**C4（仕様矛盾解決）として C カテゴリで扱えるのか、
定義変更＝ H1／H2 相当なのかの次元判定自体が D5 案件**である（Council が自分で決めれば
「自らの委譲境界を定める文書の自己改訂」に接近する — 哲学者制約 1）。

## 付記: 本審査が踏んだ薄氷（自己申告）

- **C2 は形式的に守った**（stance／confidence／集計を一度も生成していない）が、
  「12 制約すべてを満たす案」の構成は**制約の重み付けを含意する**。§4-5 の対応表は充足の有無のみを示し、
  制約間の優劣は付けていないが、B1〜B5 の分岐で「両軸から負の観測のみ」を却下理由にした箇所（案 D）は
  **観測数の多寡を根拠にしている＝投票の残滴**である。D5 はこの 1 点を割り引いて読まれたい。
- 3 軸の観測は同一モデルの人格づけで生成された（N1）。したがって本審査の死角マップ自体が
  同じ相関を持つ。**§3-3 に列挙されなかった死角が存在する可能性は、本審査では検出できない**。
