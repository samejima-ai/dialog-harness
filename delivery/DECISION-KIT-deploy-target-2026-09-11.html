前提が 3 つ食い違っている

いずれも判断の向きを変える。設問に入る前に確認いただきたい。

1. Cloudflare MCP は、このセッションからは繋がっていない

観測
セッション起動時の通知に cloudflareMCP は「認証が必要」と出ている。このセッションは非対話のため OAuth を通せない。
意味
CF の API を叩いて実機確認する経路は現時点で無い。仕様策定（SPEC / 軸の新設）は MCP 非依存で進められるが、実デプロイ検証は認証後になる。
復旧
claude.ai のコネクタ設定、または対話セッションで /mcp から認可する。

2.「無料枠を使い切った」は、移行を強制しない

実態
Supabase の超過は soft enforcement — DB 500MB 超で書込拒否、storage 1GB で停止、帯域 5GB 超でエラー。データは保持される。1 週間無操作の pause も手動復帰できる。
意味
選択肢は「移行」だけではない。減量・$25/月・移行の 3 択。移行を既定にする理由は、費用ではなく執行の型（書込拒否か日次リセットか）で選ぶべき。
反面
CF も同じ壁を持つ。2026-09-01 から D1 は無料枠超過でクエリがエラーを返す（それ以前は超過しても通っていた）。「無料枠が枯れたから CF」は、CF でも再演しうる。

3.「サーバーも含めて Cloudflare」＝ D1 必須、ではない

経路
Workers（実行層）だけ CF にし、DB は Hyperdrive 経由で既存 Postgres のままにできる。Hyperdrive は無料プランでも使える（10 万クエリ/日）。
意味
実行層と DB 層は別々に決められる。この分離が DH への波及量を左右する — 下の設問 3 が最大の分岐。
根拠
DB を D1（SQLite）に寄せると、DH の schema-evolution.md（Postgres の expand-contract 前提）と subphase-l02-domain.md の物理層が書き換え対象になる。Hyperdrive なら両方そのまま生きる。

Cloudflare で詰まる場所

D1 を選んだ場合に固い
  • 10 GB がハード上限 — 到達すると書込が失敗する（分割 = 手動シャーディング）
  • 書込 ~50 tps 程度で天井
  • DB 間 JOIN 不可 — 横断集計は別途パイプラインが必要
  • Worker 外のプロセスから接続不可 — 管理ツール・バッチが CF 内に閉じる
  • PG 固有機能（jsonb 演算子・PL/pgSQL・PostGIS・LISTEN/NOTIFY）は持ち込めない
  • node 互換は 2026-08-04 以降 既定 ON。ただし CPU 重い処理・ネイティブ依存は不向き

Supabase で詰まる場所

現在ここ
  • DB 500 MB で書込拒否（読取は生きる）
  • 1 週間無操作で pause — 手動復帰・稼働保証なし
  • Pro は $25/月（8 GB DB / 100k MAU）
  • 逆に: PG そのものなので移行の必要がない唯一の選択肢

Vercel で詰まる場所

DH の現行暗黙前提
  • Hobby は商用不可 — 収益が出た瞬間に規約違反
  • Pro は $20/人·月（座席課金）
  • 関数 CPU 4 時間 / 月・360 GB 時間の壁
  • DB は持たないので供給元が二重になる（Vercel + PG 提供元）
