DH のハーネス性能を世界水準の指標で測った。フロー指標は上位帯にあった。しかし業界がいま重心を置く受入指標は、比較そのものが成立しない。DH は人間の関与を減らすことに成功しており、その成功が、人間の関与を測定基盤にしていた指標を無効化している。

ただし「Elite 認定」ではない

DORA のクラスタ境界は毎年の cluster analysis で再導出される相対値であり、固定の合格線ではない（2022 年は Elite クラスタ自体が検出されなかった）。上表の「Elite =」はクラスタが検出された年の目安で、順位づけではなく当てはめである。

DH 側の代理定義も明示しておく — deployment = master への merge（repo 配布のハーネスゆえ別立ての deploy 工程が無い）、lead time = PR ブランチ初 commit → merge（L0 対話の時間は含まない）。n=165・単一 repo・単一運用者で、DORA の多組織サーベイとは統計的性質が違う。

3 — 唯一使える品質指標rework rate は、誰の申告も要らない

merge 後 14 日以内に、その PR 番号を明示参照する fix / revert PR が入った比。

なぜこの指標だけが使えるのか

merge 率も介入率も CTL の agreement_rate も、「人間または AI が記録したフィールド」か「人間ゲートの通過記録」に依存する。rework rate は後から実際に fix PR が出たという事実から導かれる。

誰の申告も要らず、auto-merge であろうと人間レビューであろうと同じように観測できる。ただし目標値化してはいけない — fix PR に先行 PR 番号を書かなくなるだけで下がる指標である。

4 — 総合境界に張り付く指標と、内側に散る指標

本セッションで測った 5 指標を 1 本の軸に並べると、値の出所で綺麗に分かれる。

自律度を上げるほど、自律度を評価する指標が使えなくなる

DH は「人間の関与を減らす」ことに成功している。そしてその成功が、人間の関与を測定基盤にしていた指標を無効化している。

先行分析（ANALYSIS-agentic-sdlc-world-standard-2026-08-28 §W9）は業界動向を「計測の重心は生成量から受入率・介入率・revert 率へ移った」とまとめた。しかしその 3 つはいずれも人間ゲートを前提とする指標である。ゲートを外した系では、業界がいま重心を置く指標が丸ごと使えない。

提案（いずれも提案に留め、判断は人間 = D5 に残す）

  1. rework rate を主指標に昇格する月次 harness-verify に載せれば継続観測になる。目標値化はしない（fix PR に番号を書かなくなるだけで下がる）。
  2. 受入指標は「参照系と比較しない指標」へ降格する廃止ではない。opt-in 領域（auto-merge-boundary.md）に該当した PR だけを母集団にすれば、その部分集合では人間ゲートが実在するため意味を回復する。母集団を分けるのが正しい直し方。
  3. レビュー窓を観測項目に加える5 分未満 merge 比率は、auto-merge 境界が想定どおり効いているかの直接指標になる。opt-in 領域の PR がこの比率に混ざっていたら境界の破れ。
  4. 2026-11-06 の auto-merge roll-back ゲートに本実測を入力する先行分析が「逸脱の妥当性検証」と位置づけたゲート。rework 10.9% / revert 0% / 修復中央値 0.9h が一次データになる。

5 — 限界この計測で言えないこと

限界内容
母集団n=165・単一 repo・単一運用者。DORA の多組織サーベイや dotnet/runtime（878 PR・多人数）と統計的性質が違う。帯の当てはめは目安であって順位づけではない
lead time の起点ブランチ作成起点で、仕様検討（L0 対話）の時間を含まない。DH の実作業の相当部分が対話にあることを踏まえると、実際のリードタイムはこれより長い
rework は下界10.9% と 46.1% の間のどこが真値かは決めていない
revert 0% の意味品質ではなく修復様式の反映。DH は revert より前方修正（fix PR）を採るため、dotnet/runtime の 0.6% と同列に置けない
そもそもの限界「AI 自律開発ハーネス」の業界標準ベンチマークは存在しない。 本計測は既存 SDLC 指標の転用であって、確立された benchmark suite への提出ではない

計測経路が指標を作った — 記録として

最初、master の squash commit だけで計算したとき merge 率 1.000 / human-commit 率 0.000 が出た。squash が commit 単位の情報を破壊し、かつ「master に squash commit がある」＝「merged」なので分母に不採用 PR が入り得なかったためである。

git fetch origin '+refs/pull/*/head:refs/remotes/origin/pr/*' で PR head ref を取ると 96.5% / 1.8% になり、不採用 6 件が可視化された。この文書の §4 が指摘している現象を、計測手法そのものが一度踏んでいる。

集計のみで LLM 判定を一切含まない。終了コードは常に 0（warn のみ・block しない、philosophy.md 第 6 条 人間最終承認）。
