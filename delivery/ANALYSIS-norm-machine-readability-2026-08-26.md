# 設計材料 — 規範の機械可読化はどこまでか（憲法・常識・ローカルルール・思想の 4 層）

> **本文書は判断材料であり判定を含まない**（`ANALYSIS-role-boundary-2026-08-25.md` と同型）。
> 対策の採否は次の L0 対話と人間決定に委ねる。
> 起点: v6.13.0 マージ直後の L0 対話（2026-08-26、ひでさん）における問い ──
> 「文書生成に機械可読のブロック（Frontmatter など）を設けて機械管理可能なルールで考えるか。
> 人間と同じで、憲法・常識・ローカルルール・個人の思想などでその場の動きを感覚的に近い判断が
> できるといいか。憲法とローカルルールを機械可読でジャッジする感じか」。

## 1. 前提 — DH は既に半分やっている

本件は白紙からの設計ではない。現在の DH には以下が既にある。

| 層 | 現在の実体 | 機械可読の度合い |
|---|---|---|
| 憲法 | `philosophy.md`（第 1〜9 条・L-FROZEN-PHIL） | **なし**（散文・ID なし・機械が触れる経路ゼロ） |
| 境界 | `auto-merge-boundary.md` §opt-in 領域（L-FROZEN-META） | 表形式。v6.13.0 F2 で**読み取り導出**の対象になる予定 |
| ローカルルール | `templates/rules/common/ui-baseline.rules.md` | **高い**。`B-01 MUST … ∵根拠` の形で ID・強度・根拠の 3 点セットを持つ |
| 規範メタデータ | `stage:` / `review_trigger:`（`dev-env-spec.md` §規範メタデータ） | frontmatter 相当。走査器は v6.13.0 F5 で着地予定 |
| 委譲レベル | L-FULL / L-GATE / L-FROZEN-META / L-FROZEN-PHIL | 語彙としては確立。機械判定への接続は未 |
| 常識 | **書かれていない** | ─ |
| 思想 | `history/INTENT.md`（WHY 層） | なし（判定に使っていない） |

つまり **ローカルルールは既に機械可読の形になっており、憲法だけが取り残されている**。
問いは「機械可読にするか否か」ではなく「**層ごとにどこまでの深さで機械可読にするか**」である。

## 2. 機械可読の深さは 3 段ある（混同しない）

| 段 | 意味 | 既存の例 |
|---|---|---|
| ① **参照可能** | ID があり、違反を名指しできる | `B-01` / `AD-032` / Council `f9b2c4` |
| ② **判定可能** | 違反を機械が検出できる | `harness-verifier` 7 検査 / `execution_graph.py` G-1〜G-5 |
| ③ **執行可能** | 違反したら止まる | v6.13.0 F2（opt-in 境界 → auto-merge 停止） |

**この 3 段を混同すると事故が起きる。** 本サイクルで踏んだ「`decision_category` が空欄だから
黙って捨てた」（v6.13.0 §F3）は、**管理用のフィールドを判定に使った**事故だった。
frontmatter は棚卸し・失効検出のための管理情報であって、判定の入力ではない。

## 3. 論点 A — 憲法をどの段まで上げるか

### 3-A-1. ①（参照可能）まで、という案

philosophy.md の各条・派生節に ID を振る。違反を「第 3 条 §独立コンテキスト必然性に抵触」と
名指しできるようにするが、**判定は機械にさせない**（Council または人間へ回す）。

- 長所: L-FROZEN-PHIL の意味を保ったまま、検証者が条文を指させるようになる。
  現状は「思想に反する気がする」としか言えず、v6.13.0 F1 が扱った時間的分離のような
  「条文の射程外」の発見も、指し示す先が無いと記録に残りにくい
- 長所: `crosscut-verifier-philosophy` が v5.0.0 以来 placeholder のまま実装されていない
  最大の理由は「何と照合するのか」が機械的に定まらないことであり、① はその前提を作る
- 短所: ID を振る作業自体が philosophy.md への編集であり、**L-FROZEN-PHIL に抵触する**。
  AI は提案 PR も作れない（2026-11-06 の評価ゲートまで）。人間が手で振るしかない
- 未確認: 別ファイルに「条文 ID ↔ 位置」の索引を置けば本体を編集せずに済む可能性がある。
  ただし索引と本体の二重管理は v6.12.0 I-3 が構造的に排除した形と同型の負債になりうる

### 3-A-2. ②③（判定・執行）まで上げる案

philosophy 違反を機械が検出し、停止条件に接続する。

- 長所: 今回の一連の失敗と同じ「宣言はあるが配線がない」形を憲法層でも閉じられる
- 短所: **パーサを書いた者が憲法の意味を確定させる**。凍結の意味が実質的に失われる。
  philosophy.md を L-FROZEN-PHIL に置き、AI に提案 PR すら書かせていない設計判断と正面から衝突する
- 短所（外部観測）: ガードレール製品 6 種が最大 100% の成功率で回避されたという報告がある
  （Mindgard「AI Guardrails Explained: Types, Tools and Bypass Risks」<https://mindgard.ai/blog/what-are-ai-guardrails>、
  2026-08 観測）。機械判定を信頼の終点に置く設計は一般に脆い
- 短所: 「減らす・時限化」原則（Council `f5fc45`）と衝突しうる。判定器は規範量を増やす

### 3-A-3. ゼロのまま（現状維持）

- 長所: 規範量を増やさない。2026-11-06 の評価ゲートまで待てば判断材料が増える
- 短所: `crosscut-verifier-philosophy` は v5.0.0 以来 **5 バージョン以上 placeholder のまま**であり、
  「候補のまま放置」は AD-032 が 3 ヶ月放置された前例と同型（AD-032 F4 再審ゲートが
  忘却防止のため期限を先に置いたのは、まさにこの反復を避けるため）

## 4. 論点 B — 常識の層は空欄が正解か

人間の組織では、憲法とローカルルールの間に「常識」がある。DH には無い。
これを**意図的な空欄として明文化するか**が論点。

### 4-B-1. 空欄が正解、という立場の根拠

- LLM は事前学習によって常識に相当する既定挙動を既に持っている。書けば冗長
- さらに**有害でありうる**: 「AI コーディングエージェントが指示を完全に守る割合は 3 割未満」
  「会話が長くなるほど学習済みの既定挙動が明示的な要求に勝つ」という観測が報告されている。
  逆に読めば、規範が長いほどその中の重要な一行が薄まる
- したがって規範に書くべきは **AI の既定挙動と食い違う部分だけ**。`DONT.md` が既にこの形

### 4-B-2. 反論・未確認

- 「既定挙動が常識と一致している」は**モデル世代に依存する**。世代交代で崩れうる。
  `review_trigger: model_generation` が既に存在するのは、この依存を扱う枠があるということ
- 「書かない」を規範として明文化すると、それ自体が規範量の増加になる（自己言及）
- 空欄であることを**どう検証するか**の経路がない。「書かれていないこと」は検出できない

## 5. 論点 C — 思想（WHY 層）の使い道

`history/INTENT.md` は現在、判定に使われていない。

- 提案（未判定）: 思想は**判定器ではなく優先順位表**として使う。ルールが割れたとき
  どちらに倒すかの解釈規則。人間が「なんとなくこっち」と感じられるのは、明文化されていない
  価値の重みづけを持っているためであり、それは判定ではなく重み
- **Council の重み配分（`.claude/skills/crosscut-council/council-weights.md`）が実質これを担っている**可能性がある。
  だとすれば新設ではなく、INTENT ↔ council-weights の対応を明示する作業になる
- 未確認: 軸監査が `situational_modifier` の合計 +1（宣言 0）を検出しており、
  重み表そのものが現在ずれている。対応を明示する前に是正が要る（L0/D5 専管）

## 6. 最小の入口候補（判定しない・併記）

### 候補 1: `judgeable:` メタデータを 1 つ足す

規範単位に `judgeable: machine | council | human` を宣言する。

- v6.13.0 I-4「機械判定不能なものは明示列挙し、全件を機械化したふりをしない」の一般化であり、
  発想は既に仕様に入っている
- `stage:` / `review_trigger:` と同じ任意メタデータ枠に収まる（新しい機構を作らない）
- I-5「宣言と計数器は同一 PR で着地させる」により、**宣言するなら同じ PR で数える経路が要る**

### 候補 2: ID だけ振る（判定には触れない）

`B-01` 形式を憲法・境界へ広げる。②③ には進まない。

- L-FROZEN-PHIL に抵触するため、philosophy 分は**人間が手で振る**以外に経路がない

### 候補 3: 何もしない（観測継続）

- 2026-11-06 の philosophy 評価ゲートまで待つ。判断材料が増える
- ただし `crosscut-verifier-philosophy` の placeholder 放置は継続する

### 候補 4: 逆方向 — 規範を減らす

機械可読化ではなく、**判定に使われていない規範を落とす**方向。

- `f5fc45`「減らす・時限化」の直系。v6.13.0 F5 の走査器が着地すれば実行経路ができる
- 本設計材料が扱う「4 層」のうち、実際に判定へ効いているのはローカルルールのみである可能性がある
