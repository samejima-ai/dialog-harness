## 0. Gemini への依頼文

あなたは Canvas で動く Web アプリを作るエンジニアです。以下の要件で、会議中の発言を議事ドキュメントと画面モックに変える「会議ボード」を **React の単一ファイル**で作ってください。

- 見た目のルールは §7、作ってはいけないことは §8 に従う
- 最初は §9 の「C0 検証版」だけを作り、私が確認してから次の段階へ進む
- 不明な点は勝手に決めず、コード内に `// TODO(確認):` を残して一覧で報告する

---

## 1. 目的

会議中の発言を十数秒遅れで画面に変え、参加者の認識を会議中にそろえる。

| モード | 画面 | 成功の基準 |
|---|---|---|
| 会議モード | 左：議事ドキュメント ／ 右：確定発言ログ | 参加者が「今こういう話になっている」と分かる |
| 開発モード | 左：議事ドキュメント ／ 右：画面モック（ワイヤーフレーム） | 会議後の引き継ぎ文書から本実装に着手できる |

- 利用者：進行役 1 人（操作する）、参加者 2〜6 人（話す）
- 利用環境：会議室の PC（Windows 11）＋ Chrome 最新版を大画面に映す
- 最初の利用：社内の開発会議

## 2. Canvas 版で変える前提（元仕様との違い）

| 項目 | 元仕様（ローカル／Cloudflare） | Canvas 版 |
|---|---|---|
| 文字起こし | Gemini Live API（WebSocket） | **ブラウザの音声認識（Web Speech API、ja-JP）**。使えない場合はテキスト入力 |
| 生成の呼び出し | Gemini API をサーバーから | **Canvas アプリ内の Gemini 呼び出し**（Canvas が提供するモデル） |
| 集約窓 | 8 秒 | **15 秒**（呼び出し回数を半分にする。設定で 10〜60 秒） |
| サーバー | Node.js / Cloudflare | なし（ブラウザだけで完結） |
| 保存 | ローカルファイル / R2 | Canvas のデータ保存（利用者ごとに非公開）。使えなければ localStorage |
| 出力 | ファイル保存 | Markdown のダウンロード。できなければクリップボードへコピー |
| 部品描画 | json-render | **アプリ内の自前の描画関数**（§5.5 の部品だけを描く） |

## 3. 画面

| 画面 | 役割 |
|---|---|
| 開始画面 | 議題（1 行、必須）、モード（会議／開発）、会議テンプレートを選んで開始。過去の会議を再開できる |
| 会議ボード | §4 の上部バー・左右ペイン・下部バー |
| テンプレート編集 | プリセットを複製して、区分・プロンプトを編集する |

## 4. 会議ボードの構成

- **上部バー**：議題、モード、状態（録音中／一時停止／停止）、入力レベル、経過時間、モード切替、今すぐ反映、一時停止、終了
- **左ペイン**：議事ドキュメント（区分ごとに項目を並べる）
- **右ペイン**：会議モードは確定発言ログ（時刻付き）、開発モードは工程表示＋画面モック
- **下部バー**：話し中の暫定テキスト（1 行）、直近の処理時間
- 左右の比率：会議モード 7:5、開発モード 5:7。境界はドラッグで変えられ、モードごとに覚える
- 1920×1080 でスクロールなしに両ペインの主要部分が見える

## 5. 機能要件

### 5.1 音声とテキスト入力

- 「録音開始」でブラウザの音声認識を `lang = "ja-JP"`、途中結果あり、連続認識で開始する
- 途中結果は下部バーに流す（処理には使わない）。確定結果は時刻付きで記録し、右の発言ログに出す
- 認識が止まったら自動で再開する（ブラウザは数十秒〜数分で認識を止めることがある）
- 入力レベル表示がある（マイクの音量）
- **最後の確定から 60 秒、音量があるのに確定が来ない**ときは、上部バーに黄色で「文字起こしが止まっている可能性」と出す
- 音声認識が使えない環境では、下部バーにテキスト入力欄を出し、Enter で確定発言として扱う（**この経路は常に使えるようにする**）
- 一時停止中は認識を止める

### 5.2 発言の集約

- 確定発言をためて、集約窓（既定 15 秒）ごとにドキュメント更新へ回す
- 窓の中に確定発言が無ければ呼ばない
- 前回の処理中なら次の窓へ持ち越す（並行して呼ばない）
- 「今すぐ反映」で窓を待たずに処理する

### 5.3 ドキュメント更新（正本）

- 入力：現在のドキュメント全体、今回の確定発言、議題、会議テンプレート（区分定義と追記プロンプト）
- 出力：**更新操作の配列だけ**を JSON で返させる

```json
{
  "ops": [
    {"op": "add", "section": "pending", "text": "トップに実績写真を大きく出す", "stage": 2},
    {"op": "update", "id": "i3", "text": "…"},
    {"op": "move", "id": "i3", "section": "decided"},
    {"op": "remove", "id": "i5"}
  ],
  "missing": ["誰が見るページかがまだ出ていません"]
}
```

- `stage`：1 要件（誰が・何のため）／2 画面構成（どの部品をどこに）／3 見た目（写真・文言・数字）
- 新規項目の id はアプリ側で採番する
- 雑談・相づち・言い直しは反映しない
- `requires_agreement: true` の区分（既定では「決定」）には、合意を示す発言（例:「そうしよう」「それでいきましょう」）が無い限り追加しない
- 進行役が手で触った項目（`locked: true`）への add 以外の操作は、アプリ側で捨てる
- JSON が壊れていたら、その回は何も反映せず、下部バーに「今回は反映なし」と出す
- 更新された項目を 3 秒ハイライトする

### 5.4 手動編集

- 項目をクリックすると、文言の編集・区分の変更・削除ができる
- 手で触った項目には「🔒 手動」印が付き、印をクリックすると解除できる

### 5.5 モック生成（開発モードのみ）

- ドキュメント更新が反映された直後に 1 回だけ呼ぶ。会議モード中と「モック固定」がオンの間は呼ばない
- **解放条件**：stage 2 の項目がドキュメントに 1 件以上あること。それまでは右ペインに「画面の話が出るとモックが出ます」と不足の吹き出しを出す。「今すぐモックを出す」で解放条件を待たずに生成できる
- 入力：ドキュメント全体、直近 30 秒の確定発言、部品カタログ（下表）、現在の案
- 出力：部品の木を JSON で返させる（`{"type": "hero", "props": {...}, "children": [...], "substituted": false}`）
- カタログに無い部品名・不正な JSON が返ったら、現在の案を維持して「今回は反映なし」と出す
- カタログに無い表現は最も近い部品で代用し、`substituted: true` で「代用」タグを付ける
- 変わった部品に細い青枠（2px）を付け、次の更新まで残す。各部品の左上に部品名の小さなラベルを出す
- 案のタブ（案 1、案 2…）、「1 つ前に戻す」、「2 案を並べて比較」、「モック固定」
- 右ペイン上部に工程を 1 行で表示する（① 要件 ● ② 画面構成 ◐ ③ 見た目 ○）。不足は吹き出しで最大 3 件

**部品カタログ（初版 24 種）**

| 分類 | 部品（type） |
|---|---|
| 枠 | page, header, footer, section, columns2, columns3 |
| 見出し・文章 | heading, text, catchcopy, bullets |
| 目を引く | hero（写真＋コピー＋ボタン）, image, caseCard, bigNumber |
| 操作 | button, contactForm, phone, tabs |
| 情報 | priceTable, faq, companyTable, steps |
| 補助 | mapPlaceholder, placeholder（「ここに○○」） |

- 画像は実画像を使わず、灰色の枠に「写真：○○」と表示する
- 見た目はワイヤーフレーム調。色は強調色 1 色のみ

### 5.6 会議テンプレート

- 中身：名前、区分の一覧（1〜8 個。各区分は id・表示名・説明・賛否欄の有無・合意必須）、更新プロンプトへの追記、出力プロンプト、出力ファイル名、固有名詞リスト
- プリセット 2 つ：「一般会議」（会議モードの既定、出力 minutes.md）と「サイト検討」（開発モードの既定、出力 handoff.md）。どちらも区分は 決定（合意必須）・保留・論点（賛否あり）・メモ
- プリセットは直接編集できない。複製して編集する
- テンプレートは会議の開始時にだけ選べる

### 5.7 モード切替

- 上部バーのボタン 1 つで切り替える。確認ダイアログは出さず、5 秒間「元に戻す」を出す
- 会議→開発：解放条件を満たしていれば、その時点のドキュメントからモックを 1 回生成する
- 開発→会議：モック生成を止める。案は残す

### 5.8 保存と出力

- 変更のたびに自動保存する（Canvas のデータ保存。使えなければ localStorage）
- ページを閉じて開き直しても、ドキュメント・確定発言ログ・案が復元される
- 終了ボタンで出力を作る：会議モードのみなら minutes.md、開発モードを使った会議は minutes.md と handoff.md
- handoff.md の構成：議題 → 区分ごとの項目 → 最終モックの部品の木 → 未解決の宿題
- 出力はダウンロードする。ダウンロードできない環境では「コピー」ボタンでクリップボードへ写す
- 生成の所要時間を記録し、下部バーに直近の値を出す

## 6. 非機能要件

| 区分 | 目標 |
|---|---|
| 反映の速さ | 確定から左ペイン反映まで中央値 20 秒以内（集約窓 15 秒を含む） |
| 描画 | 部品 JSON の描画 0.3 秒以内 |
| 連続稼働 | 1 時間、途中停止なし（Canvas 版の目標。元仕様は 2 時間） |
| 呼び出し回数 | 1 時間あたり ドキュメント更新 最大 240 回＋モック生成 最大 240 回 |
| 機密 | 社外秘の会議では使わない（§10 参照） |

## 7. 見た目（DESIGN.md より）

- テーマ：大画面向けのはっきりした業務系。白地、太めの文字、高いコントラスト
- 強調色：青 `#1D5FD8`（ボタン・変更枠・工程の現在位置だけに使う）
- 赤 `#C62828` は録音中・停止・エラーだけ。警告は茶橙 `#9A5B00`、ハイライトは黄 `#FFF3B0`
- 本文 20px、最小 18px。時刻は等幅
- **動きは枠・ハイライト・色の切り替えだけ**。スライド・拡大縮小・画面全体のフェードは使わない
- 発言ログの自動スクロールは、利用者が末尾を見ているときだけ。上を読んでいる間は動かさず「新しい発言 ○ 件 ↓」を出す

## 8. 作ってはいけないこと

- 確認ダイアログで画面を塞ぐこと（取り消しは「元に戻す」で行う）
- ロックした項目を AI が書き換える・移動する・消すこと
- 合意の発言なしに「決定」へ項目を足すこと
- 描画エラーで画面全体を白くすること（エラーはそのペインの中だけに出す。React の Error Boundary を使う）
- 文字起こしが止まっているのに「録音中」の表示だけを出し続けること
- 読んでいる途中でスクロールを勝手に動かすこと
- 実画像の取り込み、凝った装飾、複数色
- 話者の識別、ログイン機能、複数拠点への配信

## 9. 作る順番

| 段階 | 作るもの | 確認すること（人間が実機で確認） |
|---|---|---|
| **C0 検証版** | 音声認識の開始・停止、途中結果と確定結果の表示、AI 呼び出し 1 回（固定の文で JSON を返させる）、ダウンロードとコピー、保存と復元 | §11 の 6 項目 |
| C1 会議モード | 開始画面、会議ボード（会議モード）、集約、ドキュメント更新、手動編集とロック、保存 | 15 秒ごとに左ペインが更新される。合意なしで決定に入らない |
| C2 開発モード | 工程表示、モック解放、モック生成、案のタブ・比較・固定、モード切替 | 「トップに実績写真を大きく」で hero 部品が最上部に出る |
| C3 仕上げ | テンプレート編集、minutes.md / handoff.md の出力、処理時間の表示 | 出力から本実装に着手できる |

## 10. 既知の制約とリスク

| リスク | 影響 | 対策 |
|---|---|---|
| Canvas アプリ内の Gemini 呼び出しは仕組みが公開されておらず、使えるモデルが固定。モデル廃止で動かなくなった前例がある | ある日から生成が失敗する | 失敗時は「今回は反映なし」で画面を保つ。本番運用は元仕様（ローカル／Cloudflare）で行う |
| 呼び出しの上限が公開されていない | 会議の途中で生成が止まる | 集約窓を 15 秒に延ばし、モックは解放後・ドキュメント変化時だけ呼ぶ |
| 音声認識が Canvas の中で動くか未確認 | 音声で使えない | テキスト入力の経路を常に残す |
| 個人アカウントでは、会話内容が製品改善に使われ得る | 情報流出 | 社外秘の会議では使わない。使うなら Workspace（データ保護あり）のアカウントで |
| 共有リンクの保存先が「リンクを知る全員が閲覧・編集できる」設定になり得る | 他人に会議内容が見える | 利用者ごとに非公開の保存にする。共有リンクは社内の限られた人だけに渡す |
| コードを Canvas の外へ持ち出す公式の手段が限られる | 後で作り直しが要る | 単一ファイルの React にし、コピーして元仕様のリポジトリへ移せる形にする |

## 11. C0 検証版で確認すること

| # | 確認項目 | 結果 |
|---|---|---|
| 1 | プレビュー画面でマイクの許可が求められ、音量が動く | |
| 2 | 音声認識（ja-JP）の途中結果と確定結果が出る | |
| 3 | 音声認識が止まっても自動で再開する（5 分間話し続ける） | |
| 4 | AI 呼び出しが JSON を返し、アプリがそれを読める。所要時間は何秒か | |
| 5 | Markdown のダウンロード、またはクリップボードへのコピーができる | |
| 6 | ページを閉じて開き直すとデータが残っている。共有リンクでも同じか | |

1〜3 が動かない場合はテキスト入力で進める。4 が動かない場合は、Canvas 版をやめて元仕様（ローカル／Cloudflare）へ戻る。
