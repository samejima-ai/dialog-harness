> 人間決定に委ねる。起点: 2026-08-25 の v6.12.0 サイクルで観測された 4 件の失敗と、
> それに対する人間の診断「仕様設計と自律駆動開発は分けなくてはいけない。
> これはフラクタル原則があるからこその問題だね」。

## 1. 観測 — 同じ構造の失敗が 1 日で 4 回

| # | 事象 | 共通する形 |
|---|---|---|
| 1 | Council `f9b2c4` の是正「規範文書を auto-merge の停止条件に加える」が escalation-matrix の**促しの表どまり**で機械化されていない | 宣言はある。配線がない |
| 2 | PR #188 が「人間レビュー待ち」と自ら宣言しながらどの停止条件にも掛からず、無関係なガード（verifier ゼロ検査）に**偶然**救われた | 同上 |
| 3 | `implementer_consent` の行末コメントで**人間の事後評価が静かに消えた**（COUNCIL-LOG は全体でこの書式を常用しているのにパーサが対応していない） | 同上 |
| 4 | PR #191 が `harness-verifier/**` を触る = opt-in 領域なのに `human-review-needed` が付かず**自動マージされ、人間のレビューゲートが飛んだ** | 同上 |

4 件とも「規範に書いてあるが、**AI が思い出さなければ何も起きない**」形をしている。

## 2. 診断 — 4 件は 1 つの根の 4 つの現れ

### 2-1. 直接の引き金（#4 の場合）

`layer1-autonomous-dev/SKILL.md` は「開発中に人間へ質問しない」を全体規律とする一方、
**2 箇所だけ人間へ上げる例外**を持つ。

- H カテゴリ抵触の検知 → 即時献上（§4.5）
- **PR 作成時の opt-in 領域判定 → 「人間に『opt-in 領域に該当しますか？』を発話確認」（§7.5・L402）**

「常時聞く（L0）」から「一切聞かない（L1）」へ切り替えたとき、**例外の 2 点も一緒に落ちた**。

### 2-2. 根 — 役割の同一コンテキスト実行

philosophy 第 3 条 §サブエージェント追加の 4 基準 の 4 番目はこう書く。

> **独立コンテキスト必然性**: 同一コンテキストでは認知バイアスが生じる（例: 実装者と独立レビュアー）

ここで挙がる例は **実装者 vs レビュアー** ＝ **空間的な分離**（別エージェント）である。
**時間的な分離**（同じエージェントが L0 を演じたあと L1 を演じる）は射程に入っていない。

2026-08-25 のサイクルでは、単一セッション・単一コンテキストが L0 → Council 諮問 → L1 →
（本来分離すべき）独立検証 を**連続して演じた**。同じ根から派生した失敗が 2 つある。

- #4（opt-in 判定の脱落）= L0 の「常時聞く」から L1 の「聞かない」への切り替えが例外を巻き込んだ
- 独立検証の隔離未達 = L1 と reviewer を同一コンテキストが兼ねた（DELIVERY-v6.12.0 §L-1）

### 2-3. フラクタル原則がこれを見えなくする

philosophy 第 1 条は「同じ形状の対話パターンが全責務階層で反復する」を保証する。
**形が同じであることは、境界が消えてよいことを意味しない** ── はずだった。

しかし実運用で単一コンテキストが役割を跨ぐと、**形の同一性がそのまま境界の不可視化になる**。
L0 と L1 のゲート方針は正反対（常時問う / 一切問わない + 例外 2 点）なのに、
切り替えの瞬間に段差が無い。第 1 条は「形の保存」を保証するが、**役割遷移の可視性**は保証しない。

第 1 条には既に「依存トポロジーの追跡可能性」が前提条件として補足されている（成果物間の DAG）。
本件が示すのは、それと並ぶもう一つの前提条件がありうるということ ── **役割遷移の追跡可能性**。

## 3. 対策候補（判定しない・L0 対話の入力）

### 候補 A: 役割遷移を明示的なイベントにする

L0 → L1 の遷移を「連続した対話の続き」ではなく**離散的な受け渡し**として扱う。
献上物（SPEC/REGIME）を渡して L0 セッションを閉じ、L1 は新しいコンテキストで受領する。

- 長所: 第 3 条の 4 基準を時間軸へ自然に拡張する。根に効く
- 短所: 対話の流速が落ちる。単一セッションで回したい運用と衝突する
- 未確認: DH は元々この形を想定していた可能性が高い（L0 が生成 → L1 が受領）。
  今回の逸脱は「1 セッションで通した」ことそのものかもしれない

### 候補 B: L1 内の人間ゲートを機械側に移す

§7.5 の opt-in 判定を AI の記憶に依存させず、`auto-merge.yml` の paths filter で機械的に止める。

- 長所: AI の質に依存しない。今日の 4 件のうち #1 #2 #4 が同時に閉じる
- 短所: **`auto-merge-boundary.md` は philosophy 第 9 条の L-FROZEN-META（人間専管・恒久固定）**。
  AI は提案 PR すら作れない。**この候補は人間が手で書く以外に実装経路がない**
- 補足: GRAPH.yml には既にこのエッジが宣言されている（`auto-merge → human-P4-停止介入` /
  condition: opt-in 領域に該当）。**宣言は済んでいて、配線だけが無い**

### 候補 C: 第 1 条に「役割遷移の追跡可能性」を補足する

「依存トポロジーの追跡可能性」と並ぶ前提条件として明文化する。

- 長所: 根を思想層で捉える。GRAPH.yml に役割遷移を書く根拠にもなる
- 短所: **philosophy.md は L-FROZEN-PHIL（人間専管。AI は提案 PR も不可）**。
  かつ「条文を足す」対処は f5fc45「減らす・時限化」原則と衝突する
- 未確認: 第 1 条の既存記述で足りる可能性がある（「L0/L1/L2 は階層ではなく直交する責務」）。
  足りないのは条文ではなく**運用の分離**かもしれない ── その場合は候補 A に収束する

### 候補 D: 何もしない（観測を続ける）

N=1 の観測で規範を動かさない。同種が 3 回反復してから対処する（f5fc45 の非対称原則）。

- 長所: 規範量を増やさない
- 短所: 本件は 1 日で 4 回反復している。N=1 ではない

## 4. 人間専管の切り分け（重要）

本件の対策のうち、**AI が着手できない領域**を明示する。

| 対象 | 委譲レベル | AI の可否 |
|---|---|---|
| `auto-merge-boundary.md`（候補 B の実装先） | **L-FROZEN-META** | **提案 PR も不可**。人間が手で書く |
| `philosophy.md` 第 1 条（候補 C） | **L-FROZEN-PHIL** | **提案 PR も不可**（2026-11-06 の評価ゲートまで） |
| 運用（候補 A: L0/L1 をセッションで分ける） | 運用判断 | **人間の決定事項**。AI は提案のみ |
| 本文書のような設計材料の作成 | L-FULL | AI 可（本文書） |

**AI にできるのは、乖離を検出して報告することまで**である。今回はそれを GRAPH.yml と
`execution_graph.py` の形で実装したが、**検出器を作った PR 自身が検出対象の乖離を起こした**。
これは機構の失敗ではなく、機構が捉えるべき現象が実在することの実証である。
